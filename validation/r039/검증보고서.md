# R039 / EXP-20 검증 보고서

## 완료한 작업

기준 commit은 `8713f17eedf684b8392f3d07d9d67a3b8f8f61cd`다. R038 manifest의 Git blob `6905f5c48cf257d1088f7bf605e18b2eb1421d58`와 R037 manifest blob을 확인하고, 해당 manifest에 등록된 로컬 소스 checksum이 모두 맞는지 대조했다. 기존 파일을 고치지 않는 R039 추가 소스와 단일 파일 원클릭 설치·실행기를 작성했다.

6개의 배열 순열 × prior 2개 × arm 3개의 36회 본 실행을 정의했다. 고정되는 외부 ID·관계·score·world는 독립 입력 검산기로 재확인한다. 내부 파생 hash/slot은 고치지 않으며, 경로의 ID 대응은 evaluator에서만 수행한다.

## 실제 수행한 검사

| 검사 | 실제 결과 |
|---|---:|
| 신규 단위·입력·배포·원자료/분석 왕복 테스트 | 114개 통과 |
| 기존 R038 단위 회귀 | 72개 통과 |
| 기존 R038 실제 R035 selector 연결 회귀 | 14개 통과 |
| 기존 R037 단위 회귀 | 93개 통과 |
| 기존 R037 실제 R035 selector 연결 회귀 | 16개 통과 |
| 전체 테스트 메서드 | **309개 통과** |
| 신규 Python 소스 3.12 문법·현재 런타임 compile | **23개 통과** |

실제 실행 환경은 Linux / Python 3.13.5다. Python 3.12는 AST grammar 수준에서 검사했으며, 여기서 Python 3.12 인터프리터로 실행했다는 뜻은 아니다.

신규 테스트의 내용은 외부 ID 불변성, 모든 순열의 보존, bool/int·missing/zero 구분, world 및 slot 대응표 변조 거부, 실제 기존 selector의 ID 결합, 잘못된 parent 참조 거부, 비용 중복 합산 금지, 순열 누락/paired 비교 교란 검출, 실패·부분 원문 보존, 분석 덮어쓰기 금지 등이다.

원자료/stream/분석 왕복 테스트는 native·seed 재생을 명시적인 stub으로 대체한 배관 검사다. 이것을 native 검증 결과로 사용하지 않는다. Source/selector 검사는 Git blob이 일치하는 R035 `contracts.py`, `selection.py`, `audit.py`, `__init__.py`를 사용했지만 Graph 상태는 합성이다.

설치기 테스트는 기존 baseline 변조, 기존 R039 파일 충돌, ZIP 경로 탈출·case 충돌·symlink·checksum 오류, 특수문자가 포함된 경로, 재설치 시 동일 파일 유지, 중간 I/O 실패 기록을 검사했다. Windows에서 symlink 생성 권한을 요구하지 않도록 해당 단위 테스트는 metadata 분기를 mock으로 검사한다.

배포 후 별도 임시 디렉터리에 실제 R037/R038 소스 묶음을 배치한 뒤, 최종 R039 ZIP 설치·동일 재설치·파일 해시 재검사 및 신규 114개 테스트를 다시 수행한다. 이 배포 검사 역시 전체 native 실행 환경이 아니라 설치·연결 범위다. 단일 CMD의 내장 ZIP과 별도 소스 ZIP이 byte-for-byte 일치하는지도 확인한다. 최종 실행 결과는 별도 `HCR_R039_release_verification.json`에 기록한다.

## 실행하지 않은 범위

**이 컨테이너에서는 전체 native 통합 테스트 8개와 EXP-20 본 실험 36회를 실행하지 않았다.** 전체 native 의존 소스와 EXP-19 원자료를 컨테이너에 확보하지 못했기 때문이다. Windows CMD/PowerShell 프로세스 자체도 실행하지 않았다.

제공한 원클릭 실행기는 실제 저장소에서 전체 EXP-19 `verify`와 native 통합 검사를 먼저 수행하고, 통과하면 조건 동결 및 36회 본 실행으로 진행한다. native 통합 self-test는 기존 2개 대조 입력 × prior 2개 × arm 3개 = 12개 fresh native 실행이며, 신규 순열 결과를 사전에 선별하지 않는다. import/의존성 실패를 skip이나 합성 성공으로 바꾸지 않는다.

따라서 본 보고서에 EXP-20의 정확도·절감량·실제 경로 순서에 대한 결과는 없다. 36회 실행 결과는 사용자 환경의 raw evidence와 독립 audit를 통해 판단한다.

## 개발 중 실패의 처리

개발 초기에 테스트 fixture의 괄호 누락과 정렬된 paired 목록을 잘못 인덱싱한 assertion을 수정했다. 실패 원문은 `development_failures/`에 별도로 보존했다. 최종 조건 동결 전의 합성 self-test 실패이며, native EXP-20의 실패 또는 retry 데이터가 아니다.

## 파일과 계보

`unit_tests.txt`, `r038_unit.log`, `r038_selector.log`, `r037_unit.log`, `r037_selector.log`은 실제 검사 출력이다. `syntax.json`, `source_integrity.json`, `environment_and_scope.json`에 문법·기준 소스·실행 범위를 기록했다. 기존 release/source/evidence를 덮어쓰지 않았고, GitHub commit/push는 수행하지 않았다.
