# R040 배포 전 검증 범위

## 실제 수행한 검사

Linux / Python 3.13.5 환경에서 다음을 수행했다.

| 검사 | 결과 |
|---|---:|
| 신규 단위·합성 scheduler/control·원자료/보고 왕복·설치 경계 검사 | 75/75 통과 |
| 기존 R037 단위 회귀 | 93/93 통과 |
| 기존 R038 단위 회귀 | 72/72 통과 |
| 서로 다른 테스트 메서드 합계 | 240 통과 |
| Python 3.12 문법 검사 + 현재 interpreter compile | Python 파일 27개 통과 |
| 로컬 R037/R038/R039 제공 패키지의 manifest 대조 | 등록 파일 모두 변경 없음 |

200개 고정 seed 조합의 scheduler/독립 명세 비교는 신규 75개 중 한 테스트의 하위 조합이다.
75·93·72를 반복 실행한 것은 새 테스트 수로 중복 합산하지 않는다.
신규 제어 테스트는 SYNTHETIC-CONTROLLER-TEST-NOT-NATIVE backend를 사용하며 실제 HCC 성능 증거가 아니다.
원자료→analysis→verify 왕복 검사에서 native/seed evaluator는 명시적 stub이다. 원자료 보존과 파일 계약 검사에 해당한다.

원클릭 내장 ZIP의 byte 일치, 실제 추가 설치·동일 재설치, 설치된 사본 테스트의 최종 결과는
배포와 함께 제공하는 `HCR_R040_release_verification.json`에 별도로 기록한다.

## 개발 중 발견·수정한 문제

설치/경계 검사 추가 중 native 통합 테스트 파일이 아직 디스크에 없어서 1개 테스트가 실패했다.
`development_failures/01_missing_native_test_file.log`에 보존했다. 파일 생성 후 신규 75개를 재실행해 통과했다.
이 기록은 개발 장치의 파일 누락이며 사용자 native 실험의 실패 결과가 아니다.

## 실행하지 않은 범위

이 컨테이너에는 전체 native 엔진·의존 소스·EXP-20 원자료를 실행 가능한 사본으로 확보하지 못했다.
따라서 실제 native 통합 self-test 32 session과 본 EXP-21 72 session은 수행하지 않았다.
Windows CMD/PowerShell의 실제 실행 및 Python 3.12 interpreter에서의 실행도 수행하지 않았다.
Python 3.12는 문법 수준에서 확인했고 실제 테스트 interpreter는 3.13.5다.

확인한 연결 코드의 source of truth는 main `ef074f7991733ba0a73d870780d4873718caf1ca`의
`src/hcr/sessions.py`, `runtime.py`, `state.py` 및 R039 manifest이다.
기존 공개 prioritize_frontier API와 native checkpoint/generation 계약에 연결했다.

사용자 실행기는 반드시 기존 의존 소스 검사, EXP-20 전체 verify, native 통합 검사를 먼저 수행한다.
의존성/import/실제 API 검산 실패를 skip이나 synthetic 성공으로 대체하지 않는다.
성능 개선·조기 종료·원인 분리에 관한 실제 결론은 본 실험 원자료 생성 후 독립 검산으로 판단한다.
