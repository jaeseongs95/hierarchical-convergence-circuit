# r14 Linux 서버 C0/C1 대조 결과

같은 합성 입력을 처리한 네 번의 실행이 모두 완료됐다. C1의 전체 실행 시간은 C0보다 두 쌍에서 각각 186.801초, 192.220초 짧았고, 평균 차이는 −189.510초였다. C0 평균 대비 관측된 단축 비율은 8.83%다. 판정은 `DESCRIPTIVE_SERVER_COMPARISON`이며, 이 서버와 고정 입력에서 얻은 기술적 비교다.

## 실행과 비용

기존 SSH Test Portal 서버에서 사전에 고정한 한 번의 무작위 배정 `C1,C0,C1,C0`을 그대로 실행했다. 각 조건은 독립된 새 프로세스로 순차 실행했으며, 실패 셀 제외·재시도·실행 시간 상한 증액은 없었다.

C1 평균은 1955.914초, C0 평균은 2145.424초다. 주 비용에는 프로세스 시작, 연산, 매 tick 상태 저장과 fsync·ack, 최종 trace 저장, 자식 종료·회수와 종료 시 호스트 조회가 포함된다. 별도 평가와 검산은 이 표의 정책 실행 시간에 합산하지 않았다. 전체 연구에 기록된 경과 시간은 8531.809초로, 사전 실행 시간 상한 13100초 안에 끝났다. 준비·전송·기능 검사는 정식 표본에 포함하지 않았다.

## 동작과 품질 검산

두 조건 모두 5168번의 상태 전진과 323번의 인증 시도를 수행했다. C1은 앞선 322번에서 인증 불가능 선별을 적용했고, 마지막 시도에서 원래 인증 절차를 수행했다. region proof 횟수는 C0의 323회에서 C1의 1회로, Taylor 호출은 83653회에서 76891회로 줄었다. 이는 이 실행에서 기록된 연산 횟수이며 다른 모델의 비용 감소를 보장하지 않는다.

네 셀 모두 `CERTIFIED_WITHIN_EPS`, 후보 정답 일치, 거리 `INSIDE`를 충족했다. 봉인 후 별도 프로세스가 검산해 `PASS`했다. 실제 기록된 1292개 gate에서 중복을 제거한 323개 전체 payload에 원본 predicate를 새로 적용했고, full7 상태 일치 15507건과 성공 인증서 4개를 확인했다. 각 셀의 첫 성공은 모두 tick 5168이었다.

[오프라인 검사](verify_results.py)는 보존한 결과의 파일 해시, 소스·입력 핀, 배정, 연산 횟수, gate 상태와 digest, 성공 인증서 일치, 비용 차이의 산술을 대조한다. 이 검사는 서버에서 끝난 수치 검산을 다시 실행하거나 전체 상태 전개를 독립 재현하지 않는다.

## 환경과 해석의 한계

원래 서버의 환경은 Ubuntu AWS VM, Python 3.12.3, 논리 CPU 2개와 메모리 약 8GB였다. 두 논리 CPU는 같은 물리 코어의 SMT로 노출됐다. CPU pressure, host steal, I/O pressure, memory pressure 증가 신호를 관측했으며, 이를 이유로 셀을 제외하거나 시간을 보정하지 않았다. 신호는 호스트 수준 관측이므로 이 연구만으로 각 신호의 원인이나 지연 기여를 분리할 수 없다. wall−CPU를 순수 간섭 시간으로 해석하지 않는다.

조건별 표본은 2회다. 통계적 유의성, 일반적인 C1 우위, 새 Lightsail 서버에서의 속도 향상이나 Windows r11~r13의 가상 완료 시간을 주장하지 않는다. 새 AI Research SSH 서버에서 통과한 기능 검사 9개는 별도 환경 점검이다.

품질 판정은 작성된 합성 world, 소스에 결속된 순차 공급 결과, 공유된 고정 수치 helper와 신뢰한 기존 anchor를 전제로 한다. 비선형 전체 prefix의 독립 재전개, 전체 엔진 정확도, 일반 AI·LLM의 정확성이나 완전한 증명 유효성은 확립하지 않았다. 전체 공개 경로 처리도 완료된 것으로 판정하지 않았다.
