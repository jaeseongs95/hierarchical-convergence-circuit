# r15 새 서버 C0/C1 재현 결과

새 AI Research SSH 서버에서 같은 합성 입력으로 실행한 네 셀이 모두 완료됐고, 최종 검산도 통과했다. C1의 전체 실행 시간은 C0보다 두 쌍에서 각각 149.909초, 151.208초 짧았다. 평균 차이는 −150.558초이며, C0 평균 대비 관측된 단축 비율은 7.99%다. 판정은 `DESCRIPTIVE_SERVER_COMPARISON`이다. 이 결과는 이번 서버와 고정 입력에서 얻은 기술적 비교이며, 일반적인 성능 우위를 확립하지 않는다.

## 실행과 비용

사전에 고정한 계약과 수치 코드를 사용해 한 번의 무작위 배정 `C0,C1,C1,C0`을 실행했다. 조건별 두 개의 새 프로세스를 순차 실행했으며, 수치 예비 실험·재시도·실패 셀 제외·실행 시간 상한 증액은 없었다. 새 프로세스를 사용했다는 뜻이며, 호스트나 파일 캐시를 초기화한 것은 아니다.

| 셀 | 조건 | 전체 실행 시간(초) | 자식 CPU user+system(초) | 종료 tick | 정답·거리 |
| --- | --- | ---: | ---: | ---: | --- |
| 01 | C0 | 1885.074 | 1854.242 | 5168 | 통과·INSIDE |
| 02 | C1 | 1735.165 | 1704.369 | 5168 | 통과·INSIDE |
| 03 | C1 | 1733.741 | 1703.025 | 5168 | 통과·INSIDE |
| 04 | C0 | 1884.949 | 1854.101 | 5168 | 통과·INSIDE |

C0 평균은 1885.011초, C1 평균은 1734.453초다. 전체 실행 시간에는 프로세스 시작, 연산, 매 tick 상태 저장과 fsync·ack, 최종 trace 저장, 자식 종료·회수와 종료 시 호스트 조회가 포함된다. 별도 평가와 검산은 표의 정책 실행 시간에 합산하지 않았다. 영수증 직렬화는 공통 외부 비용으로 남는다. 연구 전체 경과 시간은 7529.738초로, 고정 상한 13100초 안에 끝났다. 최종 검산의 감독 시간은 256.470초였다.

준비 단계의 기능 검사 10개는 모두 통과했으며 정식 성능 표본에 포함하지 않았다. 기존 r14 수치·감독 엔진은 수정하지 않고, 새 adapter가 부모와 자식의 실행 파일 및 입력 디렉터리를 r15로 지정했다. 전송한 준비용 JSON 두 파일과 서명한 Git 파일의 줄바꿈을 무작위 배정 전에 LF로 맞추고 해시를 확인했다. 값과 코드는 바꾸지 않았으며, 전송본·준비 시 해시·정식 실행 시 해시를 [정규화 기록](results/runtime-normalization.json)과 함께 보존했다.

## 동작과 품질 검산

두 조건 모두 5168번의 상태 전진, 36176번의 좌표 갱신과 323번의 인증 시도를 수행했다. C1은 앞선 322번에서 인증 불가능 선별을 적용하고 마지막 시도에서 원래 인증 절차를 수행했다. region proof는 C0의 323회에서 C1의 1회로, Taylor 호출은 83653회에서 76891회로 줄었다. 이는 이번 실행에서 기록된 연산 횟수다.

네 셀 모두 `CERTIFIED_WITHIN_EPS`, 후보 정답 일치와 거리 `INSIDE`를 충족했다. 봉인 후 별도 프로세스가 검산해 `PASS`했다. 1292개 gate에서 중복을 제거한 323개 전체 payload에 원본 predicate를 새로 적용했고, full7 상태 일치 15507건과 성공 인증서 4개를 확인했다. 네 셀의 첫 성공은 모두 tick 5168이었다.

[오프라인 검사](verify_results.py)는 기존 r14 검사의 해시를 확인한 뒤 보존 파일·소스·입력 핀, 무작위 배정, 연산 횟수, gate 상태와 digest, 성공 인증서 일치 및 비용 계산을 대조한다. 준비와 정식 실행 사이의 해시 관계도 확인한다. 이 검사는 서버에서 끝난 수치 검산을 다시 실행하거나 전체 상태 전개를 독립 재현하지 않는다.

## 환경과 해석의 한계

새 서버는 Ubuntu AWS VM, Python 3.12.3, 논리 CPU 2개와 메모리 3790MiB를 노출했다. 두 논리 CPU는 같은 물리 코어의 SMT로 보였다. 운영체제 관측만으로 AWS 요금제 종류나 가격을 확인한 것은 아니다.

네 셀에서 CPU pressure, I/O pressure와 host steal 증가 신호를 관측했다. 이를 이유로 셀을 제외하거나 시간을 보정하지 않았다. 이 신호는 호스트 수준 관측이며, 개별 신호가 연구 실행을 얼마나 지연했는지 분리하지 못한다. wall−CPU를 순수 간섭 시간으로 해석하지 않는다. 일부 cgroup 루트 항목은 조회 불가로 기록됐다.

조건별 표본은 2회다. 이번 서버에서도 C1의 비용 감소 방향이 관측됐지만, 통계적 유의성이나 일반적인 C1 우위를 주장하지 않는다. r14와 표본을 합산하지 않았고, 두 서버의 순수 하드웨어 속도비·가격 대비 성능이나 Windows r11~r13의 가상 완료 시간을 산출하지 않았다.

품질 판정은 작성된 합성 world, 소스에 결속된 순차 공급 결과, 공유한 고정 수치 helper와 신뢰한 기존 anchor를 전제로 한다. 비선형 전체 prefix의 독립 재전개, 전체 엔진 정확도, 일반 AI·LLM의 정확성이나 완전한 증명 유효성은 확립하지 않았다. 전체 공개 경로 처리가 완료됐다고 판정하지 않았다. 감독의 메모리 제한 512MiB는 가상 주소 공간 제한이며, 임의로 이탈하는 프로세스 트리 전체의 격리를 보장하지 않는다.

## 보존 자료와 재검사

[comparison.json](results/comparison.json)에 네 셀의 감독·평가와 최종 판정을, [verification.json](results/verification.json)에 별도 수치 검산 결과를 보존했다. [manifest](results/manifest.json)는 함께 보존한 draw, environment, timings, final, 준비·실행·정규화와 종료 조회 자료의 해시를 고정한다. 원격 원자료는 `/home/mcpops/hcc-new-server-20261018-r15/run`에 유지했다. 모든 tick 상태와 호스트 시계열의 로컬 사본을 만들었다고 주장하지 않으며, 전체 수치 재검산에는 원격 원자료와 고정 소스가 필요하다.

```powershell
python -B evidence/new-server-replication-20261018-r15/verify_results.py
```

종료 조회에서 연구 supervisor PID 5011과 직계 자식은 나타나지 않았다. 각 정책·평가·검산 감독 영수증도 소유한 활성 프로세스 수 0을 기록했다. 다른 작업을 중단하거나 시스템 설정을 바꾸지 않았다.
