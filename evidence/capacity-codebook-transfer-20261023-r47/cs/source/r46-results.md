# R46 / EXP-92: 고정 8토큰 관계형 봉인-페이로드 코드북 전이 및 정보 경계에서 의미 불변성 채택

[R45 후속 방향 숙의](DELIBERATION.ko.md)에 따라 다변수 관계형 생산-소비 파이프라인(`R39/R40`: `role -> pair -> or0..4 -> triple/projection -> 봉인 연속 payload -> 격리 consume -> query_input -> feasible2`, 깊이 6)에서 그동안 미사용이던 `aux6(teal=6)`·`aux7(coral=7)`을 포함한 3비트 어휘의 8개 토큰 전체(`codes 0..7`)를 4개 대칭 cohort(원천 48개)로 활성화하고, 8개 전역 3비트 전단사 코드북과 6단계 전이 프로브(569회 settle)를 고정해 AI Research SSH에서 1회 실행했다. **native 384조건(`native_joint`, `native_factor`, `native_compact` 각 128조건, 질의 1,920건)·exact 128조건(질의 640건)과 336개 non-identity→identity 의미 대응(질의 1,680건)을 검산했다. 전체 단계의 유한 의미 보존 및 정보 경계 전이 판정은 `True`다.** 전체 파이프라인 40,320개 전수 실행이나 `64^n` 전체 곱집합 열거, 학습된 코드북·학습 효율·H03 구조 재사용의 증거는 아니다.

## 질문과 고정된 개입

[R45 결과](../exp-91-codebook-transfer-coverage/RESULTS.ko.md)는 단일 변수 단항 AST 파이프라인(`R35/R36`, 깊이 3, 후보 2개)에서 8개 토큰·64개 ordered 코드쌍 coverage와 `role -> expr -> feasible2 -> query2` 단계 전이를 분리했다. 그러나 다변수 관계형 파이프라인([R39](../exp-85-z-query/RESULTS.ko.md), [R40](../exp-86-factor-query/RESULTS.ko.md))에서는 다음 구조적 공백이 남아 있었다:
1. 기존 `R37~R43` 관계형 실험은 8개 어휘 토큰 중 6개(`0..5`)만 사용하고 `aux6(6)`·`aux7(7)`을 전혀 사용하지 않았으며, 고정 축 쌍(`X={0,1}`, `Y={2,3}`, `Z={4,5}`) 내부에서만 비교해 불일치 비교의 100%가 Hamming 거리 `d=1`(`0^1=2^3=4^5=1`)에 갇혀 있었다(`d=2, 3` 발생 0회, `pair` 입력 Hamming 쌍 `4/16`개만 노출).
2. `R39/R40`의 생산기(`produce`)는 `role -> pair -> or0..4 -> triple/projection` 수렴 결과인 **연속 부동소수점 상태 배열(`binding['payload']`: `slices` 8개, `factors` 12개, `xy`/`z` 6개 스칼라)**을 `payload_sha256`으로 봉인해 격리된 소비기(`consume`)로 넘긴다. 비등거리 코드북(`cnot01`, `cnot12`, `cnot20`, `cnot_chain`)이 활성 토큰의 Hamming 거리를 바꾸면 봉인된 연속 `payload` 스칼라와 `payload_sha256` 해시가 실제로 변하는데, 이때도 격리된 소비기가 모든 질의(`cond_x`, `cond_y`, `cond_xy`, `global_z`)의 정답뿐 아니라 **`native_joint`·`native_factor`(640/640 완전 정확) 대 `native_compact`(조건부 결합 손실에 따른 `544/640` 진리값 정확·`640/640` 폐포 정확·`96/640` `unique -> many` 기권)의 정보적 경계**까지 정확히 보존하는지 검증되지 않았다.

이번 R46은 원래 Program 생성기·Config·initial 0.5·guard·controller·history·Cost와 `R39/R40` 실행 경로(`execute`)를 전혀 수정하지 않고:
1. 8개 토큰 전체가 정확히 3/4 cohort(24개 도메인 슬롯 중 각 3회)에 균형 참여하고 모든 cohort에서 코드 `0`과 `1`이 서로 다른 축에 놓이도록 4개 대칭 cohort(48개 원천 `c0_R_0..c3_U_3`)를 구성했다. 이로써 16개 모든 base 조건에서 8개 코드북이 **8개 모두 서로 다른 제한 사상(`restricted_map_classes_per_base = [8]`, 무변경 `0/336`, 변경 `336/336`)**을 형성하고, 모든 코드북이 `d ∈ {0,1,2,3}` 4개 거리를 모두 실현하며 상위 `pair` 단계에서 전역 합집합 **16/16 ordered Hamming 쌍(`{0,1,2,3}^2`, 등거리 코드북 16/16·비등거리 코드북 13~14/16)**을 실제 파이프라인에서 소비하게 했다.
2. 직접 `role` 64개 입력의 4개 Hamming 동치류 분해 위에서 `role -> pair`(`4^2 = 16` 전수) 전이와 `or0..4`(`121`)·`triple`(`64`)·`projection_or2`(`16`)·`projection_or4`(`256`)·`consumer_pair`(`16`)·`feasible2`(`16`) 극값 구간 경계(`569`회 settle)를 분리해 측정했다. 계약과 입력은 [설계](DESIGN.ko.md), [동결 spec](frozen_spec.json), [방향 판정 기록](decision-record.json)에 있다.

1. **정보 경계의 코드북 불변 보존**: 8개 코드북 전체(조건 128개 × 질의 5개 = 팔당 640질의)에서 `native_joint`와 `native_factor`는 전체 진리값과 표현 폐포 모두 **640/640(100%)** 정확했다. 반면 `(X,Y)`와 `(Y,Z)` 2원 사영만 봉인하는 `native_compact`는 8개 코드북 모두에서 표현 폐포 기준 **640/640(100%)**, 전체 진리값 기준 **544/640(85.0%)** 정확했고, 조건부 결합 상관 손실이 발생하는 정확히 **96/640건(코드북당 12건)**에서 누락(`missing_z = 0`) 없이 추가 Z 후보로 인해 `unique -> many`로 기권(`extra_z = 96`)했다.
2. **전체 336짝 의미 불변 및 봉인 연속 페이로드 변동의 분리**: 3개 물리 팔 × 16개 base × 7개 비항등 코드북 = **336개 대응 조건(질의 1,680건)** 전체에서 비항등 코드북은 `identity` 기준선과 `observed`(`kind`, `selected_index`, `value`, `reason`), 중간 단계 부울 채택, 봉인 페이로드 의미 서명(`semantic_payload_signature`)을 **336/336(100%)** 그대로 보존했다. 동시에 연속 `binding['payload']` 스칼라와 `payload_sha256` 해시를 대조한 결과:
   - 등거리(isometric) 코드북(`bit_reverse`, `xor7`, 96쌍)에서는 연속 페이로드 최대 절대 차이가 `0.000e+00`(허용오차 `1e-9` 이내)였고 **96/96쌍(`96/96`)** 모두가 바이트 단위 `payload_sha256`까지 완전히 동일했다.
   - 비등거리(non-isometric) 코드북(`cnot01`, `cnot12`, `cnot20`, `cnot_chain`, `swap01`, 240쌍)에서는 Hamming 거리 재배치로 인해 `169/240`쌍에서 `payload_sha256`이 실제로 달라졌고 연속 페이로드 스칼라가 최대 `1.084243e-09` 변했으나, 격리된 소비기(`consume`)의 최종 의미 판정은 단 1건도 흔들리지 않았다.
3. **비역할(non-role) 6개 상위 단계의 완벽한 tick 불변성**: 코드북 간 총 상위 tick 차이(`141,786`~`142,434` tick)는 **100% `role_ticks`(`69,330`~`69,978` tick)에만 국한**되었다. 후속 6개 관계형 단계인 `pair_ticks`(`27,456`), `membership_ticks`(`15,648`), `triple_ticks`(`13,800`), `projection_ticks`(`2,628`), `query_input_ticks`(`5,088`), `feasible_ticks`(`7,836`)는 8개 코드북 전체에서 단 1 tick의 차이도 없이 정확히 불변(`nonrole_stage_ticks_invariant_across_codebooks = True`)이었다.

## 6단계 관계형 전이 프로브(569회 settle) 분석

- **1단계 `role`(64회 settle) → 2단계 `pair`(16회 전수 settle)**: 64개 숫자 역할 입력은 4개 Hamming 동치류(`d=0: 0.986470535294`, `d=1: 0.008324815594`, `d=2: 0.000003567999`, `d=3: 0.000000019441`, 동치류 내부 최대 편차 `1.041e-17`)로 분해된다. 이 4개 대표 스칼라의 모든 순서쌍 `4^2 = 16`개를 `pair` 커널에 주입한 결과 `16/16` 모두 정확했고(거짓 구간 `[4.091034650497e-06, 0.011626869774]`, 참 수렴값 `0.988310655569`, 수렴 tick `[25, 29]`), 40,320개 모든 3비트 전단사에 대한 `role -> pair` 동치류 합성 검사(`645,120`건)에서 오답은 `0`건이었다.
- **3단계 `or0..4`(121회 극값 settle)**: `pair` 거짓/참 극값 구간 모서리 4종(`f_min`, `f_max`, `t_min`, `t_max`)을 가변 항수 `L ∈ {0..4}`에 주입한 `1 + 4 + 16 + 64 + 36 = 121`개 조합에서 `121/121` 모두 정확했다(거짓 구간 `[1.166434879089e-02, 0.011712942728]`, 참 구간 `[0.988323570372, 0.999999838548]`).
- **4단계 생산기 봉인 투영(`triple` 64회, `projection_or2` 16회, `projection_or4` 256회 극값 settle)**: 소속 단계 극값 모서리를 주입한 `triple`(`64/64` 정확, 거짓 `[4.088463963255e-06, 0.012184183021]`, 참 `[0.987759158575, 0.987761534247]`), 2원 사영 `or2`(`16/16` 정확, 거짓 `[1.168447222685e-02, 0.011688811157]`, 참 `[0.988362873289, 0.999995907522]`), 3원 슬라이스 사영 `or4`(`256/256` 정확, 거짓 `[1.170468370758e-02, 0.011713378819]`, 참 `[0.988441849220, 0.999999838548]`) 모두 비선형 감쇠를 통해 거짓/참 여유 구간을 강하게 압축·분리했다.
- **5·6단계 격리 소비기(`consumer_pair` 16회, `feasible2` 16회 극값 settle)**: 봉인된 연속 페이로드의 거짓/참 극값 모서리를 소비기 `query_input`(`16/16` 정확) 및 최종 `feasible2`(`16/16` 정확, 거짓 eligibility `[5.297153564199e-05, 0.000260983348]`, 참 eligibility `[0.999740869356, 0.999946819905]`, tick `[32, 33, 34]`)에 주입한 결과 `none`/`unique`/`many` 판정이 100% 보존되었다. 이는 유한 극값 구간 경계 검증이며 `64^n` 전체 곱집합 열거 증명이 아니다.

## 실행·검산·비용

서버 Linux/Python 3.12.3에서 준비(`preparation`, 1.969513초, exit 0), 본 실행(`work`, 57.777520초, exit 0), 저장 감사(`audit`, 12.445608초, exit 0)의 3단계 모두 종료 코드 0으로 완료되었고, 전체 봉인 포함 **72.684063초**(상한 600초 이내)가 걸렸다. 원천 48 + 6단계 전이 프로브 569(직접 `role` 64 포함) + 상위 관계형 파이프라인 38,272 = **38,889회 actual settle**(총 1,153,068 tick, 947개 고유 trace)과 512개 평가 기록(`batch00..07`, `metrics00..07`, `sources.json`, `roles.json`, `transfer.json`, `work-ledger.json`, `summary.json`)이 100% 완료되었다. stage 240초/total 600초·worker 1/retry 0·학습/World.measure/local native 0을 지켰고, 동결 뒤 native 재실행·튜닝·조건 추가는 0이다.

로컬 saved-data 재생 검산(`analyze.py`)에서 무수정 `verify.bundle` 결과가 서버 `summary.json`과 정확히 일치함을 확인했고, 22개 합성 변조 거부(`22/22`: `revision`, `source_ref`, `joint_payload_slice`, `payload_hash`, `producer_seal`, `triple_slice`, `membership_message`, `query_slot_swap`, `query_messages`, `query_eligibility`, `selected_index`, `prefix_count`, `network_ref`, `factor_payload`, `compact_projection`, `nonbijective_map`, `inverse_vocab_mismatch`, `numeric_role_coverage`, `incomplete_8token_coverage`, `collapsed_restricted_codebook`, `incomplete_16hamming_pair_coverage`, `downstream_transfer_table_tamper`)가 모두 통과했다. scalar 최대오차는 서버 `0.0`, 로컬 `2.220446049250313e-16` / tolerance `1e-9`였다. 로컬 검산과 CS 리뷰는 작성자의 saved-data 검산이며 독립 감사가 아니다.

고유 trace 947개는 kernel+Config의 전체 canonical bytes를 확인해 **저장만** 공유했다. 모든 38,889회 추론 계산은 실제로 수행했다. 모든 phase CPU + parent 봉인 + launcher CPU 합계는 72.684487초이며, 기록 core 40.014522초, 저장 16.166732초, 원천 0.064419초, 6단계 전이 프로브(역할 포함) 0.860092초와 준비·audit·봉인 비용을 분석에 분리해 기록했다. 하위 항목 시간은 전체 process 비용의 부분집합이며 다시 더하지 않는다. 속도 비교·통계적 우위·학습 포함 효율 채택선은 없다.

## 판정과 다음 방향

**고정 8토큰 관계형 봉인-페이로드 코드북 전이 및 정보 경계에서 의미 불변성 채택.** 이 결과는 다변수 관계형 생산-소비 파이프라인(`R39/R40`)에서 8개 토큰 전체(`aux6, aux7` 포함)와 16개 Hamming 거리 쌍이 모두 활성화되어 비등거리 코드북이 봉인된 연속 페이로드(`binding['payload']` 및 `payload_sha256`)를 실제로 섭동시키는 조건에서도, 6단계 관계형 수렴 사슬의 강한 구간 압축을 통해 격리된 소비기의 질의 정답과 팔 간 정보 경계(`native_joint`/`native_factor` 640/640 대 `native_compact` 544/640·폐포 640/640·기권 96/640) 및 비역할 6개 단계의 tick이 정확히 보존됨을 보인 유한 증거다. authored codebook을 학습된 표현·H03 구조 재사용·원계산 대체·속도/효율 증거로 합산하지 않으며, 극값 경계 검증을 `64^n` 전체 곱집합 열거로 과장하지 않는다. core에 자동 반영하지 않으며, 이번 요청에서 추가 후속 실험은 자동 시작하지 않는다.
