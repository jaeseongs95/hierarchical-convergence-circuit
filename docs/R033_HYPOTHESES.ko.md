# 큰 통합가설에서 이번 구현이 시험하는 부분

첨부된 습관·고정관념 가설과 EXP-09~13 분석을 모두 한 번에 증명하려 하지 않는다.
이번 EXP-14는 “회로를 언제 유지하고, 언제 추가 계산/관측/명시적 정책 재검토를 할 것인가”를 실제 실행으로 연결한다.

| 연구축 | 이번 상태 |
|---|---|
| 근거 부족이 계산 부족인지 정보 부족인지 | paired 개입과 실제 관측 응답으로 시험 |
| 같은 정답·D라도 proof/경로가 다른가 | 최초/후속 candidate의 proof·경로·D를 그대로 보존 |
| 판단용 prior가 약한 반례를 덮는가 | route_review를 명시적 유료 개입으로 비교 |
| 강한 회로의 수정 저항 | 이번에는 정책 우회/추가 작업 비용을 기록. 고유한 회로 rigidity를 측정했다고 하지 않음 |
| 새 학습으로 수정이 다음 episode에 남는가 | frozen memory이므로 후속 |
| 공유 dependency 때문에 다른 기능이 손상되는가 | 공유 회로의 구조적 수정이 없으므로 후속 |
| consolidation·attractor width·rewiring cost | 이 단계에서 구현/입증 완료로 처리하지 않음 |

다음 단계는 EXP-14에서 구분된 실제 실패를 따른다. 추가 전개만으로 회복되지 않으면 proof 선택/판단 정책의 추가 개입을 분리한다. 질의가 불필요하게 늘어나면 전역 oracle을 runtime에 넣는 대신 공개 frontier 기반의 질의/계산 우선순위 조건을 설계한다. 정보가 없는데도 결론이 갈리면 누출·평가 결속부터 검사한다.
