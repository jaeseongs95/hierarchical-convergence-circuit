위 검사는 Linux / Python 3.13.5에서 수행했다. Python 소스 16개의 Python 3.12 문법 AST 파싱도 통과했다. 이 문법 검사는 Windows/Python 3.12 런타임 실행을 대신하지 않는다. `scripts/r034_cli.py --help`도 실제 호출하여 정상 종료를 확인했다.

선택 검산에는 재해시한 경로/부모 참조/깊이/가정/값/비용 변조를 거부하는 시험, 중복 state ID 거부, 누적 예산, 숨은 world 없이 공개 입력으로만 선택하는 계약을 포함한다. 조건표는 18개 baseline과 194개 rollout(main 182, running 대조 8, 선택 예산 대조 4)을 생성한다.

패키지의 `validation/`에 상세 JSON 보고와 각 시험의 원래 stdout/stderr 로그를 보관했다.

## 제공했지만 이 환경에서 실행하지 않은 검사

`tests/test_r034_selection_integration.py`의 **실제 저장소 엔진 통합시험 14개**, 기존 전체 엔진/도구 회귀시험, 전체 EXP-15 생성·독립 검산은 이 작성 환경에서 실행하지 않았다. 전체 실행 가능한 원 저장소 복사본을 확보하지 못했기 때문이다. 실제 GitHub 소스의 API를 읽어 연결 코드를 작성했으나, API 대조를 통합 실행 성공으로 표현하지 않는다.

따라서 이번 패키지에는 검증된 EXP-15 연구 결과나 성공률이 없다. `Run-HCR-R034.py`는 사용자 프로젝트에서 전체 회귀를 먼저 실행하고, 통과한 경우에만 조건 동결 → raw 생성 → 별도 audit → 재계산 대조로 진행한다. 통합 오류가 나오면 그 최초 로그를 남기고 중단한다.

## 연구 결과의 판정

단위시험은 명시적 새 선택 규칙과 증거 계약이 의도대로 작성됐는지 검사한다. 다음은 실제 EXP-15 결과에서 별도로 판단한다.

- 같은 정책 재시작과 route_only 재시작의 차이.
- 새 정보 없이 기존 후보의 support-aware 선택으로 출력이 회복되는지.
- 기존 정책의 추가 전개만으로 해소되는 순수 계산 부족 대조가 성립하는지.
- 원래 판단/proof와 신규 sidecar proof의 provenance 및 비용이 보존되는지.

출력 회복을 audit 통과 조건으로 강제하지 않는다. 보류·오답도 정상 기록이며 schema/parsing/runtime/measurement/evaluator 오류와 분리한다. 이번 학습량은 6회 하나이고 memory는 고정이므로 장기 학습이나 rigidity의 검증으로 해석하지 않는다.
