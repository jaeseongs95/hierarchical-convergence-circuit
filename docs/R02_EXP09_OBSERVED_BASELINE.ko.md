## 근거와 완료 상태

입력 `r02-diagnostic-01.zip`의 SHA-256은 `ec03a6e1b50ce6dfe1f8261fc2c6fde0cfcfeb78d4f37df823706c264ea933a9`다. 원본은 60회 판단 기록 뒤 요약에서 실패했다. 이 문서의 내용은 해당 원시 기록과 별도 재검산의 결과이며, 원래 run이 성공 완료됐다는 선언이 아니다.

검사 대상은 4,473개 이벤트, 3,496개 수치 tick, 60개 외부 proof/reference 평가, 10개 학습 전이, 20개 비용쌍이다. 51개 정답·9개 오답은 학습/대조/반복/수정을 섞은 건수이며 일반 정답률로 사용하지 않는다. 이번 복구 검산은 원본에 없던 시간값을 만들지 않는다.

동일 구조에서 회로 조건의 69 ticks는 pool 34 + decision 35다. graph-only의 decision은 36 ticks다. signal은 432→1,304이며 회로 조건의 pool signal은 884다. 다섯 사례의 pool signal 비중은 67.4~77.5%다. 이는 연산 비중이며 CPU 시간의 같은 비율을 뜻하지 않는다.

구조 탐색은 줄었지만 최종 decision 계산은 거의 유지한 채 pool 비용이 추가됐다. 이 다섯 작은 사례의 시간 단축은 관찰되지 않았다. primitive proof D와 proof 복원량은 짝에서 그대로였으며 macro 호출 수를 proof D로 대체하지 않는다.

## 소스 수정의 경계

현재 `runtime.py`는 revision에서 회로 사용을 끄고, `learning.py`는 오류 판단에 실제 사용된 회로만 약화한다. 참인 검증 경로를 컴파일하는 분기에는 거짓 출력의 정답이 들어가지 않는다. 현재 데이터의 재발 경로는 이 코드와 대응하지만 모든 일반 오류의 유일한 원인이라고 단정하지 않는다.

이번 repair는 요약기의 동등성 조건과 보고서 수용 경로를 고친다. 위 관측을 정상 정답으로 다시 기록하지 않는다. 전체 동작 보존 단계인 R0.2.1에는 이 데이터의 재집계 결과를 회귀 기준으로 사용하고, 새로운 학습/성능 정책은 별도 arm·버전으로 시험한다.

## 다음 별도 실험 설계

1. 같은 입력·memory에서 circuit prior를 routing에만 사용하는 조건과 판단 신호에도 넣는 현재 조건을 비교한다. 정답 label을 판단 정책에 넣지 않는다.
2. 오류가 관여한 edge/role/관측 조건에 한정한 제약을 시험한다. 같은 회로가 정상 구간에서 쓰이는 능력을 보존하는지 함께 본다.
3. 회로 후보 선택 비용과 circuit이 실제로 대체한 계산을 각각 측정한다. proof 복원·검증 비용을 숨기거나 기록하지 않은 총가속을 주장하지 않는다.
4. 회로를 유지한 약화/경쟁과 현재 강제 bypass를 분리해야 attractor 강도와 수정 난이도의 관계를 평가할 수 있다.

이 항목은 계획이며 이번 코드의 구현 성과로 세지 않는다.
