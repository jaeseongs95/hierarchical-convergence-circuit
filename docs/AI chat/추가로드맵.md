확인해보니 **핵심 계산 가설 상당수는 이미 로드맵에 들어가 있지만, 이번 6개 문서 전체를 기준으로 보면 몇 가지 중요한 축이 빠져 있거나 너무 뒤로 밀려 있다.** 특히 **물리 신경회로/I·F 계층, 동일 primitive의 A-level 반복, Decision↔Explanation 분리, 감각·착시 실험**은 현재 로드맵에 충분히 명시돼 있지 않다.

### 1. 이미 명확하게 반영된 개념

| 개념                                                            | 현재 로드맵           | 판단      |
| ------------------------------------------------------------- | ---------------- | ------- |
| Dynamic Graph → 반복 성공 → Circuit 압축/재사용                        | R0.2~R0.4        | **반영됨** |
| 익숙함 = circuit reuse, 새로움/오류 = graph expansion                 | R0.2/R0.4        | **반영됨** |
| Candidate activation / competition / inhibition / convergence | 공통 kernel, R0.3  | **반영됨** |
| 안정적으로 틀리는 `misconvergence`                                    | 기준선·품질 계측        | **반영됨** |
| A/D/M을 서로 다른 축으로 유지                                           | R0.3, R0.6, R0.7 | **반영됨** |
| Binding Continuity / identity 분리                              | 현재 엔진 + 전 단계     | **반영됨** |
| 구조적 가소성                                                       | R0.4             | **반영됨** |
| 회로 간 연결 생성·강화·약화·prune                                        | R0.4             | **반영됨** |
| 지속 내부 상태 → 나중 readout                                         | R0.5a            | **반영됨** |
| 저장 답이 아닌 부분구조의 새로운 결합                                         | R0.5b            | **반영됨** |
| 강한 연결을 weight 하나로 보지 않음                                       | 비용/품질 규칙         | **반영됨** |

실제로 통합 문서가 핵심으로 제시하는 것은 `A/D/M + Binding + 반복 → Circuit`, 그리고 실행 시 `Candidate Circuits → Competition → Convergence → Decision`이다.  현재 로드맵의 전체 순환도 표현 A → 전문 처리기 → 공통 competition kernel → 상태 전이 → readout → 외부 검증 → memory라는 형태로 상당히 잘 대응한다. 

특히 R0.4에는 단순 weight 조정이 아니라 `Fork / Join / Deactivate / Prune`, 회로 간 `CircuitLink`, 생성·강화·약화·사용중지까지 명시돼 있다. 
그래서 **“Learning = circuit formation + reinforcement + pruning + reconfiguration”**이라는 원래 개념은 구조적으로 들어가 있다고 봐도 된다. 원문에서도 학습을 바로 그렇게 정의하고 있다.

## 2. 들어가 있기는 하지만 더 명시해야 하는 개념

### A. `Binding Continuity`의 연구적 의미

코드와 로드맵에는 binding이 상당히 강하게 들어가 있다. 그런데 원래 가설에서 Binding은 그냥 타입 안전성 문제가 아니다.

> A/D/M이 실제 계산 중 **동일 의미·identity를 유지하면서 존재할 수 있게 하는 substrate-level constraint**

라는 의미다. 

현재 로드맵은 stale binding 검사, role binding, provenance 등에 집중한다. 좋은 구현 기반이지만, **v089/v090의 `semantic identity ↔ rebinding stability`를 HCR 안에서 다시 실험하는 단계**는 따로 없다.

즉 다음 비교가 로드맵에 명시적으로 하나 있어야 한다.

```text
opaque identity
vs
short uniform identity
vs
semantic identity
vs
learned/distributed identity
```

그때 볼 것은 단순 graph completion이 아니라:

```text
binding cost
wrong binding
circuit formation speed
reuse stability
novel structure transfer
```

다.

원 통합가설에서도 이 실험을 별도의 핵심 실험으로 제안한다. 

**판정: 부분 반영.**

---

### B. `Observed D ≠ Effective Internal D`

이것도 철학적으로는 들어가 있다.

현재 로드맵은 primitive proof D를 회로 shortcut 때문에 낮춰 세지 않고, runtime 비용을 별도로 측정한다. 이건 오히려 올바른 방향이다. 

원 문서가 말하는 핵심도:

```text
외부 proof는 여전히 D=5

하지만 숙련 후에는
내부 탐색량 / event / activation / binding cost가 감소할 수 있음
```

이라는 것이다. 

따라서 **`effective D`라는 숫자를 억지로 새로 만들 필요는 없고**, 현재처럼:

```text
primitive proof D
≠
runtime dependency expansions
≠
circuit hops
≠
kernel ticks
```

로 분리하는 게 오히려 더 정확하다.

다만 로드맵에 이 개념적 대응을 한 문장 명문화하면 좋다.

**판정: 실질 반영, 용어만 약함.**

---

### C. `Control Plane / Execution Plane`

원래 아이디어에서는 상당히 중요하다.

```text
Control / Plasticity
→ 경로와 연결을 천천히 구성

Execution
→ 만들어진 회로가 local하게 실행
```

이라는 구조다. A/D/M 실험의 “선택과 실행의 분리”와 물리 회로의 control/execution 분리를 연결한 것이다. 

현재 로드맵에도 compiler, plasticity, scheduler, kernel이 책임별로 분리돼 있어서 **구현상으로는 상당 부분 존재한다.**

하지만 최종 설계 원칙으로:

> `configuration is slow, execution is local`

이 명시돼 있지는 않다.

원 물리 아키텍처에서는 이것이 핵심 원칙이다. 모든 이벤트를 상위 controller가 처리하면 다시 일반 컴퓨터가 되기 때문이다. 

**판정: 구조적으로 부분 반영, 원칙으로는 누락.**

---

## 3. 현재 로드맵에서 중요한 누락

여기부터는 실제로 보강할 필요가 있다.

### ① 동일 계산 primitive를 여러 A 수준에서 재사용

이번 문서 묶음의 **상당히 중요한 핵심인데 현재 로드맵에는 약하다.**

가설은:

```text
Activation
+ Binding
+ Competition
+ Inhibition
+ Recurrence
+ Convergence
```

라는 동일 primitive가 감각·개념·직관·추론에서 서로 다른 A 수준으로 반복될 수 있다는 것이다. 

현재 R0.6은:

> 같은 문제를 다른 representation으로 옮겨 계산할 수 있는가

에 초점을 둔다. 

이것과:

> **동일한 계산 primitive 자체가 A0, A1, A2 … 에서 반복 가능한가**

는 다른 질문이다.

원래 가설은 심지어:

$$
ConvergedState(A_n)=CandidateNode(A_{n+1})
$$

까지 간다. 

그리고 단순 bottom-up pipeline이 아니라:

```text
A0 ↔ A1 ↔ A2
```

의 top-down/bottom-up recurrent constraint도 요구한다. 

**이건 현재 로드맵에 충분히 없다.**

---

### ② Decision Generation ≠ Explanation Reconstruction

이것도 빠져 있다.

원 문서에서는 상당히 명확하다.

```text
판단:
Input
→ Compiled Circuit
→ Decision

설명:
Decision
→ Graph Reconstruction
→ Language
```

즉 둘은 다른 계산일 수 있다. 

현재 로드맵은 proof와 trace를 분리하고 있어서 **사후 설명을 당시 실행으로 둔갑시키지 않는 설계는 되어 있다.** 

하지만:

```text
actual decision path
vs
later reconstructed explanation
```

을 직접 비교하는 실험은 없다.

원 가설에는 아예 별도 실험으로:

* actual execution path
* reconstructed explanation graph
* 일치율
* omitted dependency
* fabricated dependency

를 비교하도록 돼 있다. 

**판정: 기반은 존재하지만 실험 로드맵에는 누락.**

---

### ③ 감각 ↔ 직관 ↔ 추론의 공통 계산 실험

현재 로드맵 마지막에는 감각 encoder를 **나중 단계**로만 남겨놨다. 

그런데 이번 문서들의 핵심은 단순히 “언젠가 이미지 넣어보자”가 아니다.

핵심 주장은:

> 감각과 직관의 차이가 알고리즘 자체보다 **representation abstraction level**의 차이일 수 있다.

이다. 

그래서 실제 이미지 encoder를 바로 붙일 필요는 없더라도, symbolic toy task로라도:

```text
Low-A noisy pattern completion

Mid-A object/concept association

High-A hypothesis competition
```

에 **같은 convergence primitive**를 적용하는 실험이 먼저 있어야 한다.

원 통합 문서에도 이를 “동일 primitive의 A-level 재사용” 실험으로 명시해놨다. 

**판정: 현재 로드맵에서 사실상 누락.**

---

### ④ 착시 / 다중안정 / 잘못된 직관의 공통 실패모델

`misconvergence` 자체는 이미 잘 들어가 있다.

하지만 현재 HCR의 misconvergence는 주로:

```text
잘못된 prior
→ wrong stable answer
→ feedback
→ re-expansion
```

이다.

원래 문서는 여기서 한 단계 더 간다.

```text
Low-A misconvergence = illusion

High-A misconvergence = bad intuition
```

이라는 **동일 실패 형식의 A-level 비교**다. 

또한 다중안정에서는:

```text
동일 Input

State A ↔ State B
```

가 가능해야 한다. 즉 하나의 입력에 여러 attractor가 존재할 수 있다. 

현재 로드맵에는 이 **multistability 실험**이 없다.

**판정: misconvergence는 있음, illusion/multistability 일반화는 누락.**

---

### ⑤ 오류 taxonomy

현재 로드맵도 최초 실패, 안정 오답, 보류 등을 잘 나누지만, 원 통합가설이 제안한 오류 분류 전체는 들어가 있지 않다.

```text
1. Activation Failure
2. Binding Failure
3. Competition Failure
4. Misconvergence
5. Non-convergence
6. Over-compression
7. Graph Expansion Failure
```



이 taxonomy는 앞으로 버전이 늘어나면 꽤 중요해진다.

특히:

```text
틀린 후보가 이김
```

과

```text
올바른 후보 자체가 활성화되지 않음
```

과

```text
틀린 회로에서 빠져나오지 못함
```

은 전혀 다른 문제다.

**판정: 부분 반영, 표준 오류 체계로는 누락.**

# 4. 물리 하드웨어 관련 개념은 현재 로드맵에 거의 안 들어가 있다

여기는 명확하다.

현재 로드맵은 의도적으로:

> CPU symbolic reference engine에서 의미를 먼저 검증하고, 감각과 물리 하드웨어는 이후 독립 과제로 둔다.

고 되어 있다. 

그래서 다음 개념들은 **현재 버전 로드맵에는 실질적으로 없다.**

### Massive Fixed Physical Neuron Fabric

```text
물리 자원량은 대체로 고정
+
논리적 연결은 계속 변화
```

라는 모델. 

### Programmable Plasticity / I·F

가변 대상:

```text
connect
disconnect
strengthen
weaken
routing
threshold
inhibition
delay
```



### Physical system IS the network

```text
전압 = state
전류 = signal
conductance = weight
물리 연결 = topology
```

라는 최종 방향. 

### Sparse / Local / Event-driven / Asynchronous

뇌형 계산 효율의 중요한 후보 조건이다. 

### 서로 다른 시간 규모

```text
빠른 execution
중간 plasticity
느린 topology reconfiguration
```

이라는 구조도 현재 software roadmap에서는 세대·episode·memory version으로 일부 기반만 있을 뿐 **연구 축으로는 없다.** 

즉 **하드웨어 관련 철학은 현재 로드맵에서 의도적으로 보류했기 때문에 빠져 있는 상태**다.

이건 지금 당장 HCR 소스에 넣어야 한다는 뜻은 아니다. 다만 전체 연구 로드맵이라면 최종 단계에 분명히 있어야 한다.

# 5. 내가 보기엔 로드맵에 추가해야 할 축

현재 버전 순서를 크게 깨뜨릴 필요는 없다.

다만 이후 구간을 이런 식으로 보강하는 게 좋다.

```text
R0.2.x
현재 기준선 / D adaptation

R0.3
M specialization

R0.4
Structural plasticity / circuit-to-circuit connectivity

R0.5
Persistent dynamics / readout / recombination

R0.6
A adaptation

R0.6.x
Hierarchical repeated primitive
- A_n의 수렴 결과 → A_n+1 node
- 동일 kernel의 cross-A reuse
- bottom-up + top-down recurrence

R0.7
A/D/M 통합

R0.8
Decision vs Explanation
+ failure taxonomy
+ multistability / low-A vs high-A misconvergence

R0.9
Symbolic perception analogue
- low-A pattern
- mid-A concept
- high-A reasoning
- same primitive 비교

R1.0
소프트웨어 HCR 통합 reference architecture

R1.x
Sparse / event-driven / local execution backend

R2.x
Physical / neuromorphic substrate
+ programmable plasticity/control plane
+ structural routing
```

그리고 전체에 걸쳐 하나의 설계 원칙으로:

> **Configuration/learning은 상대적으로 느리게, 반복 execution은 가능한 한 local하게**

를 넣는 것이 좋다.

## 결론

**현재 로드맵이 핵심 가설을 놓친 것은 아니다.** 특히 `Graph ↔ Circuit`, competition/convergence, structural plasticity, persistent state, A/D/M 분리, revisability는 잘 들어가 있다. 

하지만 이번 여섯 문서까지 기준으로 보면 **현재 로드맵은 “소프트웨어 HCR 계산 엔진” 로드맵이고, 전체 가설의 최종 로드맵은 아니다.**

특히 추가가 필요한 핵심은 다음 6개다.

1. **동일 convergence primitive의 여러 A-level 반복**
2. **낮은 A의 수렴 결과가 높은 A의 node가 되는 계층 구조 + cross-A recurrence**
3. **Decision Generation / Explanation Reconstruction 분리 실험**
4. **multistability와 low-A/high-A misconvergence 비교**
5. **통합 오류 taxonomy**
6. **Physical substrate + Plasticity/I·F + local/event-driven execution으로 가는 장기 단계**

따라서 지금 로드맵을 그대로 개발해도 방향이 틀리진 않지만, **장기 연구지도라는 의미에서는 한 번 보강하는 게 맞다.**
