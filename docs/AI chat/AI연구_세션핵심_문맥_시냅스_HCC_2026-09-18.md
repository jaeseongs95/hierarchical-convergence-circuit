# AI연구 세션 핵심 정리

## 1. 세션의 출발점: GPT/Claude Input Cache

### 확인한 개념
- GPT/Claude에서 표시되는 `cache read`, `cached input tokens` 등의 캐시는 일반적으로 **클라이언트 PC가 아니라 모델 제공사의 서버 측 추론 인프라**에 존재한다.
- 핵심은 입력 텍스트 자체를 단순 저장하는 것이 아니라, 동일한 prompt prefix에 대해 이미 수행한 **중간 계산 상태(KV cache 계열)를 재사용**하는 것이다.
- 캐시와 실제 추론 장비가 가까이 있어야 이점이 크다.

### 클라이언트 로컬 캐시의 한계
원격 GPT/Claude API를 사용하는 구조에서 클라이언트가 자체적으로 계산 상태를 캐시하는 방식은 실익이 낮다.

```text
클라이언트 로컬 KV/Input Cache
        ↓ 대용량 전송
인터넷
        ↓
원격 추론 서버 GPU
```

- 텍스트 prompt보다 KV 상태가 훨씬 클 수 있다.
- 네트워크 전송 비용 때문에 서버 측 캐시의 장점을 잃을 수 있다.
- 따라서 원격 모델을 사용할 때는 **캐시와 추론을 서버 측에 함께 두는 구조**가 자연스럽다.

---

## 2. 이 대화에서 발생한 문맥 해석 오류

사용자의 원래 문맥:

```text
GPT/Claude의 input cache는 어디에 있는가?
→ 서버 측

그렇다면 로컬에 같은 기능을 구현하는 것은 의미가 적겠네.
→ 여기서 '로컬'은 원격 API를 호출하는 클라이언트 측
```

그러나 AI가 중간에 이를:

```text
원격 LLM ↔ 로컬 LLM
```

이라는 새로운 비교축으로 바꾸어 해석했다.

### 오류의 구조
- 장기 기억 부족이 핵심 문제가 아니었다.
- 바로 직전 담화에서 이미 확정된 referent를 유지하지 못했다.
- `로컬`을 `클라이언트 로컬`이 아니라 `로컬 LLM 실행 환경`으로 재해석했다.
- 사용자가 제시하지 않은 새로운 분기를 추가한 **과추론/잘못된 binding** 형태로 볼 수 있다.

### HCC 관점에서 볼 수 있는 해석
이 사례는 다음처럼 모델링할 수 있다.

```text
현재 Context Graph
GPT/Claude
   ↓
Input Cache
   ↓
Server-side

새 입력:
"로컬에 저 기능을 구현"

정상 binding:
server-side ↔ client-side local

실제 잘못된 route:
local → local LLM
```

즉 문맥 오류를 단순한 "기억 실패"가 아니라 다음 요소로 분해할 수 있다.

- referent retrieval 실패
- semantic binding 오류
- context compatibility 무시
- 강한 다른 회로의 잘못된 활성화
- route selection 오류
- terminal adoption 오류

이는 HCC의 **misconvergence** 연구와 직접 연결될 수 있다.

## 3. 인간은 문맥을 어떻게 이해하는가

인간은 앞 문장을 문자 그대로 계속 재독해하기보다는, 현재 대화가 무엇에 관한 것인지 **상황 모델(situation model)** 을 지속적으로 갱신하는 것으로 볼 수 있다.

단순화하면:

```text
새 입력
  ↓
단어/문장 의미 활성화
  ↓
현재 상황 모델과 결합
  ↓
referent / 관계 후보 활성화
  ↓
최근성 + 중요도 + 문법 + 의미적 적합성
  ↓
가장 자연스러운 binding 선택
  ↓
상황 모델 갱신
```

예:

```text
현재 모델:
GPT/Claude
  └─ Input Cache
      └─ Server-side
```

여기에:

```text
"그럼 로컬에 저 기능을 구현하면?"
```

이 들어오면,

```text
"저 기능"
→ 직전의 Input Cache

"로컬"
→ 직전의 Server-side와 대비되는 Client-side
```

로 해석되는 것이 자연스럽다.

### 연구적으로 중요한 점
문맥 이해는 단순한 token sequence 보존보다:

- node 활성화
- identity 유지
- semantic continuity
- binding
- relation 유지
- 현재 graph와의 compatibility
- 후보 경쟁

으로 보는 편이 HCC의 계산 관점과 잘 맞는다.

## 4. 시냅스는 고정된 배선이 아니라 계속 변하는 구조라는 관점

사용자의 관점:

> 시냅스는 계속 진화한다.

엄밀한 생물학 용어로는 `진화`보다는 **가소성(plasticity)과 재구성**에 가깝다.

핵심 아이디어:

```text
현재 연결 구조
   ↓
경험 / 외부 자극
   ↓
특정 연결 반복 활성화
   ↓
연결 강도 변화
   ↓
다음 계산에서 활성화 경향 변화
```

즉:

```text
회로 → 사고
```

만 있는 것이 아니라,

```text
현재 회로
   ↓
사고 / 경험
   ↓
연결 상태 변화
   ↓
다음 회로
   ↓
다음 사고
```

라는 재귀적 구조로 생각할 수 있다.

---

## 5. HCC의 Circuit에 가소성 관점을 적용

기존 HCC 개념:

```text
Dynamic Graph
   ↓
검증 / 반복 성공
   ↓
Circuit 형성
   ↓
빠른 재사용
   ↓
실패 / novelty / conflict
   ↓
Graph 재확장
```

가소성을 넣으면:

```text
Dynamic Graph
   ↓
특정 dependency / binding / route 성공
   ↓
Circuit 형성
   ↓
반복 사용
   ↓
연결 상태 변화
   ├─ 강화
   ├─ 약화
   ├─ 억제
   ├─ 경쟁
   └─ 소멸 가능성
   ↓
재사용 성향 변화
```

### 구현 변수 후보
- `connection_strength`
- `activation_preference`
- `binding_strength`
- `context_compatibility`
- `reuse_strength`
- `competition`
- `reexpansion_threshold`

이 변수들은 한 번에 합치지 않고 독립 조작 가능성을 먼저 검증해야 한다.

## 6. 강한 Circuit이 항상 좋은 것은 아니다

현재 context와 잘 맞는 circuit보다 과거에 강하게 학습된 circuit이 먼저 활성화될 수 있다.

예:

```text
현재 context:
server-side cache ↔ client-side local

강한 기존 association:
local → local LLM
```

만약 후자가 경쟁에서 이기면:

```text
현재 문맥과 맞지 않는 강한 Circuit
        ↓
잘못된 binding
        ↓
잘못된 route
        ↓
안정적인 오답
```

이 가능하다.

즉 HCC에서:

> 강한 Circuit = 정확한 Circuit

으로 놓으면 안 된다.

다음은 구분되어야 한다.

- strength
- context compatibility
- accuracy
- stability
- revisability
- computational cost

이 구조는 **misconvergence**, 고정관념, 잘못된 직관의 계산 모델로 연결될 수 있다.

---

## 7. 아기의 뇌 성장 관점

아기의 뇌 발달을 HCC와 연결하면 Circuit을 단순히 저장된 경로가 아니라 **발달하는 계산 구조**로 볼 수 있다.

초기 아이디어:

```text
초기 상태
   ↓
외부 자극 / 경험
   ↓
관계 형성
   ↓
반복 사용
   ↓
강화 / 약화 / 경쟁 / 제거
   ↓
안정된 Circuit
```

또한 낮은 수준에서 안정된 계산이 높은 수준 계산의 node가 될 수 있다.

```text
낮은 수준 Circuit
        ↓
상위 Graph의 primitive/node
        ↓
더 높은 수준 Circuit 형성
```

이는 HCC의 **Hierarchical Convergence**와 직접 연결된다.

## 8. 사용자의 초기 핵심 가설: 시냅스를 새로 만드는 것이 아니다

이번 세션에서 가장 중요하게 재확인된 초기 가설이다.

사용자의 원래 생각은:

> 학습하면서 시냅스를 계속 추가하는 것이 아니라, 처음부터 매우 많은 잠재적 시냅스/연결을 준비해 두고 외부 자극에 의해 그 연결들 사이의 관계와 강도가 형성된다.

즉:

```text
초기 상태
= 매우 큰 잠재 연결 공간

외부 자극
   ↓
특정 연결들의 관계 형성
   ↓
반복
   ↓
강화 / 약화 / 비활성화
   ↓
일부 연결은 소멸 가능
```

핵심은 **edge creation보다 기존 잠재 연결의 상태 변화**다.

---

## 9. Fixed / Overcomplete Substrate Hypothesis

이 초기 가설을 계산적으로 정리하면 다음과 같다.

### 기본 구조

```text
Latent Substrate
┌──────────────────────────┐
│ 매우 많은 잠재 연결      │
│ A-B, A-C, A-D, ...       │
│ B-C, B-D, ...            │
└──────────────────────────┘
             ↓
          경험 입력
             ↓
      Binding / 관계 형성
             ↓
       Strength 변화
             ↓
         Circuit 출현
```

새로운 edge를 생성하는 대신 기존 edge의 상태를 바꾼다.

예:

```text
초기:
edge exists = true
active      = false
binding     = none
strength    = 0
```

경험 후:

```text
A → B
binding  = relation_x
strength = 0.25
active   = true
```

반복 성공 후:

```text
A ═══> B ═══> D
0.93      0.88
```

구조 자체를 새로 생성한 것이 아니라 **잠재 연결 중 일부가 기능적 Circuit으로 수렴**한 것이다.

## 10. Graph와 Circuit의 관계를 다시 볼 가능성

이 관점을 적용하면 Graph와 Circuit이 완전히 별개의 자료구조일 필요가 없을 수도 있다.

기존 관점:

```text
Graph
  ↓ compile
Circuit
```

대안 가설:

```text
하나의 underlying / latent graph

약하고 불확정적이며 경쟁하는 연결
→ Dynamic Graph 상태

강하고 안정적으로 수렴된 연결 subset
→ Circuit 상태
```

즉:

> Graph와 Circuit의 차이는 별도의 구조가 아니라 동일 substrate의 서로 다른 수렴 상태일 수 있다.

그러면 Graph↔Circuit 전환은:

```text
Latent connectivity
     ↓ 경험 / 외부 자극
Unstable Graph
     ↓ 반복 / 경쟁 / 강화
Stable Circuit
     ↓ novelty / conflict
Graph 재확장
```

이라는 **상태 전이**로 표현할 수 있다.

## 11. Circuit Formation의 재정의 가능성

이 가설에서는:

```text
Circuit formation
≠ 새로운 edge를 물리적으로 추가
```

대신:

```text
Circuit formation
= 기존 잠재 연결 공간에서
  특정 연결 subset이
  binding을 획득하고
  강화되고
  경쟁에서 살아남아
  안정된 계산 구조로 수렴하는 과정
```

으로 정의할 수 있다.

이렇게 보면 학습의 핵심 대상은:

- edge creation
보다는
- allocation
- binding
- strength
- competition
- inhibition
- pruning / deactivation
- reactivation

이 된다.

## 12. 현재 연구 주장 수준

### observed / 기존 연구와 부합하는 부분
- 인간의 시냅스 연결 강도와 구조는 경험에 따라 변할 수 있다.
- 인간 문맥 이해는 직전 단어 하나만이 아니라 더 넓은 담화·상황 모델을 사용한다.
- referent resolution과 semantic integration은 문맥 이해에서 중요하다.

### hypothesis
- HCC의 Circuit이 실제로 동일 latent substrate의 수렴 상태로 표현될 수 있다.
- 강한 Circuit과 context compatibility의 경쟁으로 문맥 오류·고정관념·misconvergence를 설명할 수 있다.
- 대규모 고정 잠재 연결 공간에서 binding/strength 변화만으로 충분한 학습 구조를 만들 수 있다.
- 인간의 발달 과정과 HCC의 Graph→Circuit 수렴 과정 사이에 계산적으로 의미 있는 대응이 존재한다.

### 주의
이 가설은 인간 뇌의 실제 생물학적 메커니즘이 HCC와 동일하다는 주장이 아니다.

현재는:

> 생물학적 관찰에서 영감을 얻은 계산 가설

수준으로 유지한다.

## 13. 다음 판별 실험 후보

가장 직접적인 실험은 두 모델을 비교하는 것이다.

### A. Dynamic Edge Model

```text
필요할 때 새로운 edge 생성
→ 반복 성공
→ 강화
```

### B. Preallocated / Overcomplete Model

```text
edge를 처음부터 충분히 준비
→ 처음에는 inactive/unbound
→ 경험에 따라 binding/strength만 변경
```

### 동일하게 고정할 조건
- task
- topology budget
- observation
- world
- seed
- scheduler
- selector
- resource budget
- evaluator

### 비교할 측정량
- Accuracy
- Convergence
- Stability
- Revisability
- Graph expansion
- Binding/reference failure
- Route selection
- Misconvergence
- Relearning
- Computational cost별 개별 metric

### 핵심 판별 질문
> 새로운 연결을 동적으로 생성하지 않고도, 충분한 잠재 연결 공간의 상태 변화만으로 동적 Graph 형성·Circuit 수렴·재확장을 재현할 수 있는가?

## 14. 이번 세션이 HCC에 추가한 핵심

이번 세션의 가장 중요한 연구적 연결은 다음이다.

```text
문맥 이해
   ↓
Situation / Context Graph 유지
   ↓
Referent Binding
   ↓
Circuit Competition
   ↓
선택 / 수렴
```

그리고 장기적으로:

```text
거대한 잠재 연결 공간
   ↓
외부 경험
   ↓
Binding
   ↓
강화 / 약화 / 억제 / 소멸
   ↓
Circuit 출현
   ↓
계층적 재사용
   ↓
novelty / conflict
   ↓
Graph 재확장
```

즉 HCC의 Circuit을 **새로 만들어 저장하는 객체**가 아니라,

> **미리 존재하는 잠재 연결 공간에서 경험에 의해 관계와 강도가 수렴하여 나타나는 안정된 계산 상태**

로 볼 수 있다는 새로운 구현·이론 방향이 구체화되었다.
