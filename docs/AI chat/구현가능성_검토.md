# 계층적 수렴-회로 가설 — 프로그램 구현 가능성 검토

검토일: 2026-09-16. 근거 문서: `계층적_수렴_회로_통합가설_감각_착시_ADM_2026-09-16.md`.

## 1. 판정

문서의 중심 구조는 기능적 소프트웨어 아키텍처로 구현 가능하다. 여러 표현 수준의 후보 상태를 유지하고, binding과 재귀적 경쟁을 수행하고, 검증된 반복 그래프를 재사용 가능한 연산 구조로 바꾸고, 불일치 시 다시 동적 탐색으로 전환하는 실행계를 구성할 수 있다.

다만 세 판정을 분리한다. 첫째는 이런 상태·연산·학습 경로를 프로그램으로 정의할 수 있는가이며 가능하다. 둘째는 그 구현이 새로운 문제에서 정확도와 효율을 개선하는가이며 실험할 질문이다. 셋째는 실제 감각·직관·착시의 생물학적 공통기제를 설명하는가이며 이 구현 검토로 판정하지 않는다. 구현 가능성을 세 번째 주장과 혼동하지 않는다.

이 문서는 완성된 수치 알고리즘 하나를 지정하지 않는다. 48절의 F_M은 구체적 상태 갱신식과 학습 규칙이 정해지기 전까지 여러 구현을 허용한다. 이는 구조가 구현 불가능하다는 뜻이 아니라, 다음 단계에서 실행 규칙을 선택하고 고정해야 한다는 뜻이다.

## 2. 첨부 문서의 핵심을 구현 요소로 대응

| 문서 요소 | 가능한 소프트웨어 구성 | 아직 선택해야 할 명세 |
|---|---|---|
| Hierarchical Representations / A | 수준별 표현 공간, 후보 집합, 상·하향 연결 | 각 수준의 의미, encoding/decoding, 후보 수와 연결 의미 |
| Binding Continuity | 영구 identity와 표현을 분리한 node handle, 관계·버전·provenance | 역할-대상 결합 방식, 불확실한 binding 유지·갱신 규칙 |
| Activation/Competition/Inhibition/Recurrence | 활성값과 흥분·억제 연결을 반복 갱신하는 공통 kernel | 업데이트 방정식, 이웃 범위, damping, 잡음, 안정성 조건 |
| Convergence | 상태 변화량·후보 간 margin·지속 시간의 관측기 | 수치 수렴과 결정 가능성 기준; 환경 정답은 별도 |
| Novelty/Error → Graph Expansion | 불일치·낮은 margin·회로 적용조건 실패에 따른 후보/관계/경로 추가 | 확장 연산, 예산, A/D/M 변경 정책, 실패 조건 |
| Graph Validation → Circuit Compilation | 검증된 subgraph의 재사용 연산화, 원래 의존관계의 certificate 보존 | 일반화 범위·실행 전제조건·무효화·재검증 정책 |
| Plasticity / Control Plane | 느린 연결 강화/약화/추가/삭제, 회로 version 관리 | 어떤 피드백이 무엇을 바꾸는지와 학습률/망각/안정성 |
| Physical Neural Substrate | 먼저 CPU의 상태·희소 그래프·이벤트 시뮬레이터 | 이후 뉴로모픽/전용회로의 fan-in, 정밀도, 지연, 배치 제한 |

이는 문서 7·15·21·25·29·31·44·48절을 읽어 만든 구현 제안이다. 구체 알고리즘 선택을 문서에서 이미 확정한 것처럼 취급하지 않는다. Binding은 문서대로 네 번째 A/D/M 축이 아니라 실행의 기반 조건으로 둔다.

## 3. 현재 v091과의 차이

라이브러리에 보존된 `Run-v091-Auto.ps1`의 내장 ZIP SHA-256을 확인했고 manifest에 기록된 214개 파일 해시를 검사했다. `design091.py`, `run091.py`, `bridge091.py`, 집계·검증 파일의 상위 구조를 읽었으며 자동 실행 스크립트는 실행하지 않았다.

현재 v091은 사전 고정된 문제·조건에 따라 compare/select/facts/rule/final 호출을 배정하고, `/api/chat` 원응답을 보존하며, proof와 D를 사후 검증하는 실험기다. 반복되는 경험에 따라 자체적인 활성 회로·연결·학습 상태가 바뀌는 범용 재귀 인지 엔진을 구현한 버전은 아니다.

따라서 현재 코드를 폐기하거나 그대로 '뉴런 회로'라고 이름만 바꾸는 대신 두 역할을 분리하는 것이 맞다.

- 기존 실험기: 기존 증거·baseline·고정 primitive proof 검증·호출/비용/버전 기록을 보존하는 평가 기반.
- 새 실행 엔진: activation, binding, recurrence, circuit memory, expansion, plasticity를 실제 상태 갱신으로 실행하는 대상.

LLM을 붙인다면 후보 생성/표현 변환 등 명시적인 인터페이스를 통해 사용한다. 동일 LLM을 여러 번 호출하는 것만으로 회로 학습이 구현됐다고 주장하지 않는다. 현재 결과를 유지한 원문과 새로운 계산 시도를 분리한다.

## 4. 설계에서 먼저 해결해야 할 다섯 계약

### 4.1 재귀 회로와 proof DAG는 다르다

재귀 회로는 a→b→a처럼 순환할 수 있다. 원래 proof DAG validator가 이 회로를 직접 읽으면 cycle로 거부하는 것이 정상이다. validator를 느슨하게 바꿀 문제가 아니다.

회로 topology, 시간별 실행 event trace, 정당화를 표현한 proof graph를 분리한다. 시간적으로 펼친 원인 그래프와 원래 primitive rule proof가 어떤 관계인지 명시한다. 역방향 피드백이 있다는 이유만으로 그것을 논리적 전제로 간주하지 않는다.

### 4.2 A, D, 반복 횟수, 계산 비용을 구분한다

A는 표현 수준이다. D는 의존 구조다. 서로 다른 수준 간 신호 전달 횟수나 recurrent 업데이트 수를 D_DAG로 부르면 안 된다. 문서의 'Observed D ≠ Effective Internal D'를 구현할 때에도, 새 엔진이 직접 기록한 실행량과 접근하지 않은 LLM 내부 깊이를 혼동하지 않는다.

예를 들어 원래 세 규칙 proof를 하나의 macro로 실행하더라도 원래 primitive로 펼친 proof D는 그대로 유지한다. macro 호출 depth, kernel updates, 노드/간선 활성 수, 검증·설명 비용은 별도로 측정한다. 저장된 macro를 1단계로 표시한 것을 원래 논리 증명의 D가 줄어든 증거로 쓰지 않는다.

### 4.3 안정성과 정답을 구분한다

수렴 판정은 상태 변화량, margin, 지속성 등 내부 관측이다. 정답은 실제 환경 결과나 검증기로 별도 판정한다. 높은 margin을 calibrated confidence로 간주하지 않는다. 후보 2개가 같은 값으로 고정된 상황은 안정적이지만 결정하지 못한 상태다. 같은 후보가 잠시 1등인 것만으로 수렴했다고 선언하지 않는다.

범용 recurrence가 모든 설정에서 수렴한다는 보장은 없다. budget exhausted/oscillation/ambiguous stable/wrong stable를 구분해 관측하고, 수렴 실패를 강제로 정답으로 처리하지 않는다.

### 4.4 회로 압축은 출력 캐시와 구분한다

같은 입력 문자열의 답을 저장하는 것은 유용할 수 있으나 문서가 말하는 관계 구조의 circuit compilation 전체를 구현한 것은 아니다. 재사용 가능한 조건, 변수 binding, 수행 연산, 원래 proof certificate, 가정과 환경 version을 보존해야 한다.

제한된 symbolic primitive 영역에서는 검증된 subgraph를 조건부 macro로 컴파일하는 시작점이 가능하다. 이는 기능적인 graph→circuit 모델이며, 곧바로 분산 신경회로의 학습 구현과 동일하지 않다. 그 다음 단계로 실제 weight/routing 변화 및 희소 활성화 비용을 측정하는 구현을 확장할 수 있다.

압축 회로가 적용되는 비용 외에 matching, training, 검증, 설명 복원 비용도 포함해야 한다. 기존 사례의 성공 경로를 저장하는 것만으로 새로운 사례의 정확도·계산 감소가 보장되지는 않는다. 학습 episode와 evaluation을 나누고 evaluation에서 학습할지 여부도 미리 정한다.

### 4.5 그래프 확장은 사후 원문 보정과 다르다

이전 실험의 '무보정'을 버릴 필요가 없다. 원본 output t를 보존하고, 별도 오류 관측과 feedback을 받은 뒤 새 상태/새 후보 t+1을 생성하면 된다. 최초 시도 성과와 전체 적응 후 성과·비용을 함께 보고한다. 잘못된 과거 parent를 바꿔 최초 실행이 성공했던 것처럼 만드는 것은 여전히 금지한다.

정답을 알려주는 evaluator가 학습/추론의 내부 경로로 몰래 답을 주는지 통제해야 한다. 명시적으로 허용한 외부 feedback은 사용할 수 있지만 그 시점과 정보량을 기록한다.

## 5. 실제로 수행한 좁은 수치 점검

`convergence_probe.py`는 두 후보를 가진 표현 수준들에 동일한 bounded softmax recurrence를 적용한다. 업데이트는 입력 evidence/prior, 같은 후보의 활성 지속, 다른 후보 억제, 다른 수준의 피드백을 합친 뒤 damping을 적용한다. 이 식은 검토를 위해 선택한 한 가지 구현이며 첨부 문서가 이 식을 확정했다는 의미가 아니다.

14개 공학 시험이 통과했다. 주요 예시는 다음과 같다.

| 조건 | 수치 관측 |
|---|---|
| 한 수준의 명확한 입력 | 첫 후보로 안정 |
| 같은 모호한 입력, 시작 상태 두 종류 | 서로 다른 두 안정 상태로 수렴 |
| 정확한 대칭 상태 | 상태는 안정되지만 margin=0으로 결정 보류 |
| 두 수준, 약한 하위 evidence만 존재 | 동일 kernel로 두 수준 모두 첫 후보 선택 |
| 같은 하위 evidence + 강한 반대 상위 prior | 두 수준이 높은 margin으로 반대 후보에 안정 |
| 하위 evidence만 강하게 수정 | 하위는 전환하지만 상위는 이전 잘못된 선택 유지 |
| prior/recurrence를 명시적으로 약화하는 추가 외부 개입 | 두 수준 모두 첫 후보로 전환 |
| 강한 억제 피드백·무감쇠 설정 | 관측 budget 안에서 수렴하지 않음 |

정답 인자는 `settle` 함수에 없다. 외부 toy truth와의 비교는 결과를 받은 후 따로 수행했다. 따라서 내부 안정 상태를 자동으로 정답으로 간주하지 않는다. 마지막 두 조건도 검토자가 설정한 개입이며 자동 학습의 성과가 아니다.

**이 점검에 구현하지 않은 것:** graph expansion, circuit compilation, 학습된 binding, 학습된 A-level encoder, 자율 control policy, 구조 가소성, 실제 뉴로모픽 회로. 감각/착시 데이터나 LLM 응답도 사용하지 않았다. 작은 상태 동역학의 실행 가능성을 확인한 것이며 가설 전체의 실증 결과는 아니다.

## 6. 첫 통합 원형의 권장 경계

전체 소스 재설계 전에 작은 CPU reference kernel을 별도 폴더에서 만들고 다음 순환을 연결하는 것이 적절하다. 이는 후속 설계 제안이며 이번 검토에서 구현한 전체 기능이 아니다.

입력 → 후보 활성화·binding → 계층간 재귀 경쟁 → 안정성 관측 → 외부 검증 → 성공 graph의 학습/컴파일 또는 오류에 따른 확장 → 다음 입력에서 재사용.

핵심 인수시험은 다음이다. 수렴하는 경우뿐 아니라 오수렴·모호함·비수렴을 분리해야 한다. 반복 성공 이후 단순 exact-input cache가 아닌 구조적 재사용을 보여야 한다. novel/예외 입력에서는 압축 회로에 고착되지 않고 실제 후보/관계가 확장되어야 한다. 설명은 실행 event 또는 compiler certificate에서 복원하고 존재하지 않은 dependency를 만들어 넣지 않아야 한다. 원형/회로 on-off/학습 on-off/feedback on-off를 구분해 정확도와 전체 계산 비용을 비교해야 한다.

공통 kernel을 낮은 A와 높은 A에 동일하게 호출할 수 있다는 사실만으로 두 도메인에서 유효한 지능을 확인한 것은 아니다. 입력 adapter와 task feedback을 명시하고 representation 외 처리 규칙을 동일하게 고정한 대조가 필요하다. 원래 문제의 goal 판정을 유지하는 task domain이 첫 실험에 가장 분명하다. 그 후 noisy pattern completion 등 다른 도메인으로 확장할 수 있다.

## 7. 물리 하드웨어와 기존 구현 사례

전용 하드웨어가 없어도 기능적인 동역학·학습/회로 구조는 먼저 소프트웨어로 모델링할 수 있다. 이번 작은 수치 검사도 CPU에서 수행했다. 이후 event-driven/sparse 실행을 목표로 하려면 중앙 제어기가 매 event의 정답을 계산하는 구조가 아니라, 국소 message/edge와 느린 configuration update의 경계를 맞춰야 한다. Python prototype의 실행 성공만으로 실제 회로의 전력·지연·규모 이점을 입증하지 않는다.

외부 확인은 첨부 가설의 생물학적 참/거짓을 대신하지 않는다. 아래는 일부 기능의 구현 선례다.

- Ramsauer et al., Hopfield Networks is All You Need: 연속 상태의 associative update와 fixed-point 종류를 다룬다. 이 가설 전체가 해당 모델과 같다는 뜻이 아니다.
- Soar 공식 Procedural Knowledge Learning: 하위 문제해결 경험을 새 production으로 컴파일하여 유사 상황에서 재사용하는 chunking을 설명한다. 프로그램으로 graph-like reasoning을 재사용 연산으로 바꾸는 구현 선례다.
- Lava 공식 문서: process/model 분리와 CPU ProcessModel 예제를 제공한다. software 검증과 향후 neuromorphic backend 분리를 설계할 때 참고할 수 있다.

구체 원문 위치는 `sources.json`에 보존했다. 생물학적 동일성, 이 가설의 신규성, 범용성, 현재 GPU에서의 최대 규모는 이번 검토의 판정 대상이 아니다.

## 최종 판단

문서의 중심 계산 구조를 프로그램으로 구현하는 데 서로 양립하지 않는 필수 조건은 발견하지 못했다. 지금 필요한 것은 그림의 모듈명을 그대로 클래스명으로 옮기는 작업이 아니라, F_M·binding·convergence·compilation·feedback의 실행 명세를 정하고 같은 kernel 안에서 연결하는 것이다. 기존 v091은 계속 원형 상태로 보존하고 새 엔진의 검증 기반으로 활용하는 편이 맞다.
