# R36 실행 전 판별 계획

| 관측 | 얻는 정보 | 다음 판단 |
|---|---|---|
| 역할·AST 중간 출력과 최종 strict가 모두 맞고,C/T6함수 구별 및192변형 불변성이 성립 | R35의 배타적 입력 밖에서도 같은 생성 규칙이 실제 겹침 조합을 처리한다 | 해당 유한 단일변수 문법만 채택. 다음은 별도 계약으로 다변수 결속 상관관계 검토 |
| 역할 matcher부터 오류/동적 보류 | 기존 필드 표현/native 역할 일치의 경계 | 첫 실패 원천·drive·trace를 보고하고 원인 판별을 다음 과제로 둔다 |
| 역할은 맞지만 AST 중간 출력이 틀리거나 함수가 축약됨 | 조합 회로/native 수렴의 의미 보존 경계 | 최종 정답이 우연히 맞아도 일반 조합 채택 보류. 해당 패턴과 최초 실패 stage 보존 |
| 역할·AST는 맞지만 최종 상태/query/불변성이 틀림 | 승격 packet·상태 분류·별도 T 소비의 경계 | 해당 경로의 실패를 보존하고 다음 원인 판별로 넘긴다 |
| source/원자료/수식 결속 실패,timeout/메모리/파일 경계 초과 | 엔지니어링 또는 증거 불충분 | 이론상 음성으로 세지 않고 판정불가로 보고. 같은 입력의 맹목 재실행·상한 사후 확대는 하지 않음 |

native의 오답·보류는 프로토콜 실패와 구별한다. exact가 set oracle와 다르면 baseline 결함으로 해당 비교를 보류한다. 새 실행이 필요하면 확인한 원인과 새로 얻을 정보가 있는 별도 계약을 먼저 만든다. 현재 run/code/input/threshold를 덮어쓰지 않는다.
