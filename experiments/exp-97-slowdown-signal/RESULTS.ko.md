# R51 / EXP-97 결과: 수렴 지연은 보지 않은 조건에서도 prior 의존 판단을 잘 가려냈지만, "증거가 0 이하인 edge가 있으면 보류"라는 입력 규칙과 정확히 같은 셀을 골랐다

[설계](DESIGN.ko.md)(SHA-256 `ec3dd3e1…f775b`), [동결 spec](frozen_spec.json)(`c0bf4272…3e26`), [입력 핀](input_manifest.json)(`db91f339…a945`)은 본 실행 전에 고정했고 실행 뒤 바꾸지 않았다. 본 실행 1회, 결정성 재실행 1회. 번호 R51 / EXP-97은 잠정이다.

## 1. 판정 (설계 7·8절 규칙 그대로)

**해석: `SLOWDOWN_REDUNDANT_HERE`.** tick 신호는 실재하고 문턱도 새 조건으로 이전됐다. 그러나 이 과제에서는 입력만 보는 규칙이 같은 일을 추가 계산 없이 해냈다. 시험 전체 AUC는 `ticks_total` 0.985, `min_score` 0.990으로 차이 −0.005(기준 +0.05 미달)다.

| 예측 | 판정 | 내용 |
|---|---|---|
| P1 신호 존재 (AUC ≥ 0.80) | supported | 시험 전체 `ticks_total` AUC 0.985 |
| P2 문턱 이전 (e0 = 1.0, 새 강도) | supported | 재현율 1.0, 재사용 보존율 1.0 |
| P3 약한 e0에서 절대 문턱이 무너진다 | **falsified** | 재현율 1.0, 재사용 보존율 0.984. 무너지지 않았다 |
| P4 약한 e0에서 `min_score`가 0.9 미만으로 떨어진다 | **falsified** | 0.989. 떨어지지 않았다 |
| P5 `goal_margin` 또는 `ticks_decision`이 1위 | **falsified** | 1위 `min_score`, 2위 `ticks_decision`. `goal_margin`은 7위 |
| P6 영합 집계 일치 | supported | 정의상 항등, 집계 오류 없음 |

틀린 예측 셋 가운데 둘(P3, P4)은 같은 오판에서 나왔다. 설계 2절에서 "e0가 약하면 증거가 모두 양수여도 OFF가 False인 표적이 생길 것"이라 가정했는데, 실제로는 **e0가 0.2든 1.0이든 OFF는 e1 > 0일 때만 True였다**(85개 조합 전부). 그래서 입력 규칙이 약한 e0에서도 그대로 통했고, tick이 더 잘할 여지가 처음부터 없었다.

## 2. 신호별 결과 (시험 집합: 적용 대상 348셀, 표적 84 = 포획형 80 + 미결정형 4)

| 신호 | 얻는 시점 | 보정에서 정한 문턱 | AUC | 재현율 | 재사용 보존율 |
|---|---|---|---:|---:|---:|
| `min_score` | 입력만 | 증거 최솟값 ≤ 0 | 0.990 | 1.000 | 0.985 |
| `ticks_decision` | 판단 뒤 | ≥ 35 | 0.986 | 1.000 | 0.985 |
| `ticks_total` (주 신호) | 판단 뒤 | ≥ 70 | 0.985 | 1.000 | 0.985 |
| `ticks_pool` | 회로 적용 전 | ≥ 35 | 0.984 | 1.000 | 0.977 |
| `uncertainty` | 입력만 | ≥ 0.7 | 0.866 | 1.000 | 0.530 |
| `prior` | 입력 + memory | ≥ 0.825 | 0.860 | 1.000 | 0.398 |
| `goal_margin` | 판단 뒤 | (모든 셀이 해당) | 0.465 | 1.000 | 0.000 |
| `pool_margin` | 회로 적용 전 | (모든 셀이 해당) | 0.464 | 1.000 | 0.000 |

하위 집합별 `ticks_total`: T-a(본 강도, 새 입력) AUC 0.976, T-b(새 강도, 새 입력) 1.000, T-c(새 강도, 옛 입력) 1.000. 보정 집합에서는 0.986이었다.

세 가지가 눈에 띈다.

1. **tick 문턱과 입력 규칙이 고른 셀이 완전히 같다.** 시험 집합에서 `ticks_total ≥ 70`이 고른 88셀과 `min_score`(증거 ≤ 0)가 고른 88셀은 동일한 집합이다(사후 확인). 둘 다 표적 84개 전부와, 표적이 아닌 4셀을 골랐다.
2. **최종 여유(margin)는 신호가 아니다.** `goal_margin`·`pool_margin`의 AUC는 0.5 아래다. 포획된 판단의 goal 상태는 최소 0.734이고 80개 중 61개가 0.99 이상이다. 회로 때문에 바뀐 판단은 **확신에 찬 채로** 끝난다. prior 의존 여부는 "얼마나 확신하는가"가 아니라 "거기까지 얼마나 오래 걸렸는가"에 남는다. 동기 문서의 "빠르고 안정적으로 틀린다"에서 "안정적으로"는 맞고, "빠르게"는 이 조건에서 맞지 않는다.
3. **tick의 분리 폭은 2다.** 표적의 최소 `ticks_total`은 70, 보류되지 않은 비표적의 최대는 68이다. 격자 간격 0.1에서는 깨끗이 갈리지만 여유가 얇다. 더 촘촘한 격자에서 유지되는지는 보지 않았다.

비표적인데 보류된 4셀은 모두 n=6, e1 = −0.2다(e0 = 0.2, 0.4, 0.6, 0.8). 회로가 선택됐고 ON도 OFF도 False를 채택했으며 tick은 263~264로 시험 집합에서 가장 느렸다. **가장 느린 셀은 판단이 바뀐 셀이 아니라 prior가 거의 이길 뻔한 셀이다.** tick은 "회로와 증거가 맞서고 있다"를 재는 것이지 "판단이 바뀌었다"를 재는 것이 아니다.

## 3. 보류의 결과와 비용

보류는 새 정보 없이 OFF 결과를 채택하는 것이다. `ticks_total` gate 기준, 시험 집합(전체 426셀):

| 항목 | 값 |
|---|---:|
| 보류된 셀 | 88 |
| 닫힌 세계에서 사라진 포획 오답 | 80 / 80 |
| 열린 세계에서 사라진 올바른 True | 80 |
| 미결정 → False로 바뀐 셀 | 4 |
| 닫힌 세계에서 남는 오답 True (ON·OFF 모두 True, 관측 자체가 오도) | 260 |

| 정책 | kernel tick 합 | expansion 합 |
|---|---:|---:|
| always-OFF | 14,140 | 852 |
| always-ON | 31,981 | 504 |
| `ticks_total` gate (보류 셀은 ON + OFF 모두 지불) | 34,844 | 680 |
| `min_score` gate를 같은 방식으로 실행 | 34,844 | 680 |

- 포획 오답은 전부 사라지지만, 같은 80셀이 열린 세계에서는 올바른 보완이었다. 설계 2절에 적은 대로 보류는 영합이고, 어느 쪽이 이득인지는 환경 기저율에 달려 있다. 이번 실험은 그것을 정하지 않는다.
- tick 기준으로는 always-OFF가 가장 싸고(always-ON의 44%) 포획도 0건이다. 회로를 쓰는 쪽의 이득은 expansion 감소뿐이다(852 → 504, gate는 680). EXP-44 이후 반복된 "expansion은 줄고 tick은 는다"와 같다.
- `min_score` 규칙은 ON을 돌리기 **전에** 판정할 수 있으므로 실제로는 보류 셀에서 ON 비용을 내지 않아도 된다. 위 표는 두 gate를 같은 방식으로 실행했을 때의 값이고, 입력 규칙의 실제 하한은 더 낮다. tick gate는 그럴 수 없다.

## 4. 곁가지 관찰 (사전 예측 아님)

- **다른 edge의 증거가 약하면 포획이 깊어진다.** n=20은 e0 = 1.0(R50)에서 e1 = −0.3까지 포획했는데, e0 = 0.2에서는 격자 끝인 −0.5까지 포획했다. n=9는 e0 = 0.2에서 −0.3까지 포획하고 −0.4·−0.5에서는 미결정이 됐다. 엔진의 prior가 "묶인 edge 중 가장 불확실한 것"에 비례하기 때문에, 한 edge가 흐릿하면 다른 edge의 반대 증거를 누르는 힘도 커진다.
- e0 = 0.4~0.8에서는 포획 범위가 e0 = 1.0과 같았다.

## 5. 이 결과가 뜻하는 것과 뜻하지 않는 것

- R50의 사후 관찰(경계 근처에서 느려진다)은 보지 않은 강도·입력에서 재현됐다. 수렴 지연은 "회로 prior와 증거가 맞서는 중"이라는 내부 표지로 쓸 수 있다.
- 그러나 **이 과제에서는** 그 표지가 입력에서 바로 읽히는 것과 같다. 2-edge chain에서 회로 OFF의 판단은 "모든 edge의 증거가 양수인가"로 정해지고, 회로가 판단을 바꾸는 곳은 정확히 그 조건이 깨진 곳이기 때문이다. tick을 재확장 신호로 쓰자는 제안이 이득을 가지려면, prior 의존 여부를 입력에서 한눈에 읽을 수 없는 과제가 있어야 한다.
- 그런 과제가 이 엔진에 있는지는 모른다. 후보는 경로가 여럿이라 OFF 판단이 edge 하나의 부호로 정해지지 않는 topology, 여러 회로가 경쟁하는 입력, 긴 경로다. 이번 실험은 그것들을 보지 않았다.
- 보류만으로는 영합을 벗어나지 못한다. 벗어나려면 보류 뒤에 새 정보를 얻어야 한다(측정 요청).

## 6. 실행·검산

- 기록 호스트: Linux x86_64, glibc 2.39, Python 3.12.3. `src/hcr` 수정 0, `World.measure` 0, revision 요청 0, feedback 소비 20(학습). ON 평가 573(보정 147 + 시험 426), OFF 평가 85.
- R50과 겹치는 memory 7개(n = 3, 4, 5, 6, 9, 12, 20)의 문서 해시가 R50 기록과 같음을 실행 중 확인했다.
- 본 실행 wall 9.5초. 결정성 재실행에서 시간 필드를 뺀 전 필드 동일([determinism.json](../../evidence/slowdown-signal-20261120-r51/determinism.json)).
- 2차 경로 검산 [verification.json](../../evidence/slowdown-signal-20261120-r51/verification.json), 기록 호스트에서 `status = PASS`. R50의 v2 방침을 처음부터 적용했다.
  - `AdaptiveSession`으로 다시 학습해 memory 9개를 비트 단위로 재구성.
  - 658 평가 전부를 `AdaptiveSession`으로 다시 실행. 채택값·status·선택·expansion·network별 tick이 658/658 일치(필수).
  - 표적, 문턱, AUC, 재현율, 보존율, 판정, 해석을 probe와 별도 코드로 재계산해 일치(필수. tick과 입력 기반 신호에 대해).
  - goal·activation의 부동소수 값과 margin 계열 두 신호는 호스트에 따라 마지막 자리가 다를 수 있어 진단으로만 보고한다(기록 호스트에서는 차이 0).
  - AUC 계산과 표적 분류의 순수 함수(`core.py`)는 probe와 검산이 함께 쓴다. 같은 작성자의 검산이며 독립 감사가 아니다.
- core 회귀시험(`scripts/selftest.py`)은 변경 뒤 다시 실행했다. 이번 변경은 새 파일 추가뿐이다.

## 7. 공개해야 할 절차상 사실

1. 순서: 설계·spec 동결 전 trace에서 network별 tick을 읽는 방법 확인 1회(빈 memory, 진실한 양수 chain) → 설계·spec 동결 → 도구 작성 → `--smoke`(학습 3 episode) → 본 실행. 본 실행 전에 평가 결과는 보지 않았다.
2. 보정 집합은 R50에서 이미 본 조건이다. 거기서의 tick 양상은 R50 결과(전체 tick 합)로 일부 알고 있었다. network별 tick과 문턱은 이번에 처음 계산했다.
3. 2절의 "두 gate가 같은 셀을 고른다", "분리 폭 2", "가장 느린 셀은 비표적", 4절 전체는 결과를 본 뒤 추가한 탐색 분석이다.
4. 설계의 가정 하나(약한 e0에서 모두 양수인 표적이 생긴다)가 틀렸고, 그 때문에 "tick이 입력 규칙을 이기는지"를 가를 조건이 시험 집합에 사실상 없었다. 이 실험은 tick 신호의 **이전 가능성**은 시험했지만 **입력 규칙 대비 우위**는 제대로 시험하지 못했다. `SLOWDOWN_REDUNDANT_HERE`는 "이 과제에서"로 읽어야 한다.
5. 설계·구현·실행·검산을 한 작성자(AI 연구 보조)가 한 세션에서 수행했다. blind 토론·교차검토·별도 Judge는 없었다.

## 8. 한계

- 2-edge chain 하나, 길이 2 회로 하나, 기본 Config의 결정적 격자 비교다. AUC는 이 유한 격자의 순위 통계이고 모집단 추정이 아니다. 독립 표본이 아니다.
- 격자 간격 0.1. e1이 0과 0.1 사이일 때 OFF 판단이 어디서 뒤집히는지, tick 분리(70 대 68)가 유지되는지 보지 않았다.
- 문턱은 "보정 표적의 최솟값" 한 가지 규칙만 썼다. 다른 규칙에서의 재현율·보존율 곡선은 AUC로만 요약했다.
- tick 수는 R50에서 두 호스트 사이에 같았으나 이번 문턱 근처(70 대 68)에서도 같은지는 다른 호스트에서 검산을 돌려 봐야 안다.
- 인간의 직관·"쎄한 느낌", LLM 내부, 생물학에 대한 주장이 아니다.

## 9. 다음 후보 (이번 사이클에서 시작하지 않음)

1. **보류 뒤 측정 요청으로 고리 닫기**: 보류한 셀에서 불확실한 edge의 고정밀 측정을 요청하고 그 관측으로 다시 판단한다. 영합을 벗어나는 유일한 길이다. 신호는 값싼 입력 규칙과 tick 둘 다 써서, 측정 횟수 대비 두 세계의 정답률을 비교한다. 엔진의 `request_revision`은 외부 오답 feedback 뒤에만 열리므로, "내부 신호로 요청을 여는" 연구 외피가 필요하다.
2. **입력 규칙이 통하지 않는 과제 찾기**: 경로가 둘 이상인 topology(diamond), 회로 둘의 경쟁, 길이 3~4 경로에서 "OFF 판단 = 한 edge의 부호"가 깨지는지 먼저 조사하고, 깨지는 곳에서 tick과 입력 규칙을 다시 비교한다. tick 신호의 고유 가치는 여기서만 판가름난다.
3. **고착 규칙 계약 심사**(R50에서 이월): H07을 시험 가능하게 만드는 학습 규칙 개입.
