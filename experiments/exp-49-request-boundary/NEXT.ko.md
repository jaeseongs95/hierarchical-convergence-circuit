# R068 이후: 요청·학습·세션 지속 효과 분리

R068은 현재 자율 conflict 요청 경로가 없다는 API 경계를 확인했다. 다음에는 이미 지원하는 외부 피드백 경로의 효과를 분리할 수 있다.

1. e0=1, e1=+0.8의 단일 후보 조건을 공통으로 동결하고 최초 판단을 저장한다. R067 원입력에서 e0를 바꾼 새로운 조건임을 기록한다.
2. 외부 피드백을 독립 reference로 산출한다. 피드백 없는 군, 동일한 피드백을 받은 군을 구분하며 정답인 세계에 거짓 오답 피드백을 주지 않는다. synthetic 피드백은 연구 결과에 합산하지 않는다.
3. 동일한 오답 피드백으로 생성된 동일 memory checkpoint에서 (a) 기존 세션의 정상 revision과 (b) 동일 관측을 받는 새 세션을 비교한다. memory 변경·mode·revision authorization 차이를 공개하고, 완전히 고정할 수 없는 차이는 인과 결론의 한계로 둔다.
4. 요청 발생/미발생, 요청 edge, 같은 정보 재제공/새 측정, 최초·후속 readout/adoption을 분리한다. 실제 sensor 예산과 edge 수를 각각 센다. 여러 약한 edge의 선택 최적화까지 확장하지 않는다.
5. host의 과거 사실 conflict 비교를 native가 했다고 표현하지 않는다. 자율 trigger를 원한다면 과거 사실·freshness 표현과 trigger 계약을 먼저 별도 동결하고 최소 변경으로 검증한다.

아직 실행하지 않은 방향이며, 이전 관측과 양립하는 설명을 구별할 수 있는지 먼저 설계를 점검한다.
