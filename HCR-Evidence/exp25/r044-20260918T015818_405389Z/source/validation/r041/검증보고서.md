Parent capsule·전체 raw→analysis→verify 파이프라인 테스트의 native/seed 재생은 명시적 stub이다.
합성 결과를 HCC native 연구 결과로 사용하지 않는다.

## 설치기 검증

최종 ZIP 생성 후 별도 임시 저장소에서 Python 설치기를 실행하고, checksum·재설치 idempotence·
기존 파일 불변성·충돌 시 무수정 중단·설치 사본의 신규 테스트를 검사한다.
해당 최종 결과는 별도 `HCR_R041_release_verification.json`에 기록한다.
설치 fixture는 검증된 기존 addon 패키지와 `src/hcr` 디렉터리 표시만 포함하며 실제 native 엔진은 없다.
CMD 내장 base64를 복원한 ZIP이 별도 ZIP과 바이트 단위로 같은지 확인한다.

## 미실행 범위

전체 native 엔진과 EXP-21 raw의 실행 가능한 사본이 이 컨테이너에 없다.
따라서 native 통합 self-test 61회, 본 EXP-22 108회, EXP-21 raw 전체 verify는 여기서 실행하지 않았다.
실제 native 검사는 사용자 실행기의 필수 단계다. 의존성 누락이나 native 실패를 skip으로 넘기지 않는다.
Windows CMD/PowerShell과 Python 3.12 실제 인터프리터도 미실행이다. 3.12 문법 검사는 수행했다.
최종 ZIP/내장 payload 검산은 Windows launcher 실행 자체의 검증과 구별한다.

## 개발 실패 보존

`development_failures/`의 두 로그는 테스트의 이전 버전·커밋 기대값 잔존을 보여준다.
이 기대값을 현재 EXP-21 기준으로 갱신한 후 전 검사를 통과했다. 실패 로그는 삭제하지 않았다.
실험 결과나 기존 raw를 수정해서 검사를 통과시킨 것이 아니다.

## 판정

검사한 범위의 source/합성 제어/보고/패키지 계약은 통과했다.
Native 실행 가능성은 사용자 저장소의 필수 통합 검사를 통과해야 확인된다.
소스 작성·검사와 본 실험 완료를 같은 상태로 보고하지 않는다.
