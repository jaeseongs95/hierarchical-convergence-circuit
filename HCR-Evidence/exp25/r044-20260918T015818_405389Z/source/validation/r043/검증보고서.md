# R043 생성 환경 검증 기록

## 완료

Python 3.13.5 / Linux에서 단위·오류 주입 **60/60 통과, skip 0**.
Python 파일 **27개**의 AST 문법 검사 통과. 실행기/CLI help 호출 성공.
초기·확장·최종 테스트 로그를 모두 보존했다. 이 로그들은 개발 검사이며 연구 반복 실험이 아니다.

GitHub main 조회 commit은 `eedb04f90f02cf3c55693d493d33db18f96a23b5`이었다.
대화에 첨부된 R042 payload의 manifest Git blob을 직접 재계산하여 현재 GitHub의
`3e1447a50b2e0938a10468ce428b6b76a8d28d86`과 일치함을 확인했다.
그 manifest의 기존 파일 41개도 SHA-256 검사를 통과했다.
R041 scheduler/runtime/contracts/trial_audit는 커넥터에서 현재 commit 원문을 읽고 API 경계를 검토했다.

단위 검사 범위: ID 외 입력/world/seed 변경 탐지, 12조건/6쌍/6회귀 구성,
ID 순위와 slot 결정 구분, 로그용 ID 읽기 계수, 실제 차이와 측정 불가의 구분,
보조 결과 차이 보존, 미측정 null, 독립 분석 재생/변조 탐지, 최초 실행 실패/부분 evidence,
synthetic backend 거부, append-only 파일, archive 경로/내용/충돌 검사, 실패 설치 기록.
설치 테스트의 기준선 검사는 가상 fixture로 분리했다. 실제 native 설치 통과를 의미하지 않는다.

## 수행하지 않은 검사

전체 native dependency check를 실제 호출했으나 생성 환경에 `r038_early_adoption` 등
기존 전체 저장소 의존 소스가 없어 ModuleNotFoundError로 중단됐다. 원문 로그를 보존했다.
이 실패를 skip 또는 native 통과로 기록하지 않았다.

따라서 실제 native 통합 self-test, EXP22/23 raw 전체 replay, EXP24 12조건 실행은
**이 환경에서 수행하지 않았다**. Windows CMD/PowerShell 프로세스도 직접 실행하지 않았다.
이 패키지는 신규 소스/문법/단위 검증을 마친 상태이며 전체 native end-to-end 검증 완료 상태가 아니다.

사용자 저장소의 원클릭 파이프라인은 실제 의존성 확인·기존 raw 검산·native self-test를
필수 단계로 실행한다. 어느 단계든 실패하면 본 실험을 계속하지 않으며 최초 로그와 부분 evidence를 남긴다.
실제 HCC/LLM 연구 결과는 이 검증 기록에 포함하지 않는다.
