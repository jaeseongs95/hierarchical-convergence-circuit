# R046 배포 전 검증 범위

## 수행한 검증
- GitHub 최신 main을 `3f07c81e27984e712f8cf3dc4b52ab2194dfbc53`로 확인했다.
- 실제 native 소스 8개를 확보하고 전체 Git blob SHA가 해당 commit과 일치함을 확인했다. 모델을 흉내 낸 mock kernel이 아니라 이 native 핵심 함수를 직접 실행했다.
- 구현·오류 주입·설치기 및 native core 검사 96개를 통과했다. 새 순차 carry smoke에는 formal score 0.92 대신 0.85를 사용했고, 연구 population에 합산하지 않았다.
- 저장된 EXP-26 OFF 6조건의 입력·state signature·ticks·결과를 같은 native core에서 재현했다. 이는 회귀이며 새로운 독립 evidence가 아니다.
- 원천 A와 B 24조건의 raw 기록 및 stream 대조, 별도 scalar/proof 검산, 집계표 생성 경로를 임시 폴더에서 검사했다. 이 harness는 구현 점검이며 formal EXP-27 결과가 아니다.

## 직접 수행하지 않은 범위
이 환경에는 이전 전체 실행기의 `r038_early_adoption` 등과 EXP-26 raw 전체가 없다. 따라서 기존 EXP-26 full verify를 포함한 사용자 저장소의 전체 OneClick 파이프라인을 끝까지 실행했다고 주장하지 않는다. 새 native core와 새 어댑터의 직접 실행·검산은 위 범위대로 수행했다. 필수 부모 full verify는 실제 원클릭 실행에서 생략할 수 없다.

Windows CMD / Windows PowerShell 자체는 이 Linux 환경에서 실행하지 않았다. launcher의 payload·checksum·고정 section 및 잘못된 WindowsApps 정규식 제거는 파일 수준으로 검증한다. byte/code 검증을 Windows 실행 검증으로 표시하지 않는다.

## 개발 실패 보존
`development_failures/001_initial_smoke.txt`는 carry gate의 reason과 terminal reason이 같은 변수로 덮어쓰였던 첫 개발 실패를 보존한다. 수정은 evidence 필드 분리이며 native 계산 규칙이나 효과 예측 변경이 아니다.
초기 proof 재사용의 사후 처리 경계는 release 전 source review에서 전향적 candidate 생성으로 수정했다. 상세 내용은 DESIGN의 construct 점검에 기록했다.

최종 ZIP의 별도 설치 검사에서 unittest discovery가 외부 PYTHONPATH에 의존하는 결함을 발견했다. 테스트 진입점에 저장소 src/tools를 명시했고 환경변수 없는 subprocess import 회귀를 추가했다. 원래 실패는 development_failures/002에 보존했다.
