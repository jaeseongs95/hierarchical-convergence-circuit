# R045 제작 환경 검증 기록

## 완료한 검증

최신 main `3bfeb64af877a7512071798fd77d8eba839760a1`을 GitHub 연결 도구로 확인했다. 제공된 R044 소스 ZIP의 manifest Git blob을 현재 저장소의 `86eaf459d963220845512c766b707ba3b4c0a1f6`와 대조했고, 그 manifest가 선언한 49개 파일의 해시를 확인했다. 새 패치는 기존 runtime 파일을 수정하지 않는다.

최종 **90개 단위검사, 실패 0·오류 0·skip 0**. 실행 환경은 Python 3.13.5 / Linux다. 이 검사는 합성 fixture와 mock 기반의 입력 격리, 단계별 노출 계산, typed measurement failure, 보고 분기, ID 투영, append-only 저장, installer 충돌, 최초 실패 보존, 분석 재계산·봉인 검사다. native HCC 계산을 실행했다는 증거가 아니다.

Python AST 구문검사, 두 CLI help 호출도 수행했다. `syntax.json`과 `command_results.json`에 실제 범위를 저장했다. 최종 배포 ZIP/내장 CMD payload 검증은 별도 전달되는 `HCR_R045_release_validation.json`에 기록한다.

## 수정 과정에서의 실패

44·75·89개 단계별 검사 로그를 보존했다. ID decision 서명 변조를 확인하는 새 테스트를 추가한 첫 90개 실행에서는 1개가 실패했다. 테스트가 배열 인덱스로 OFF 조건을 바꾸고 ON 대조를 확인한 것이 원인이었다. 조건명과 gate로 변경할 fixture를 선택하도록 테스트 코드를 수정한 뒤 90개 전체를 재실행했다. 최초 실패 로그는 `unit_signature_control_initial_failure.log`, 수정 후 로그는 `unit_final.log`다. 이 과정은 작성 단계의 테스트 수정이며 본 실험의 retry·원자료 수정이 아니다.

## 수행하지 못한 검증

전체 native 의존 소스와 EXP-25 전체 raw가 이 컨테이너에 없다. 전체 검증 명령을 실제로 시도했으며 `ModuleNotFoundError: r038_early_adoption`에서 실패했다. 그 로그는 `native_dependency_check_unavailable.log`다. 이 실패를 통과·skip으로 집계하지 않는다.

따라서 **실제 EXP-26 native 실험, 부모 native 재실행, native 독립 state/proof replay, Windows CMD/PowerShell 더블클릭 실행은 이 제작 환경에서 검증하지 못했다.** 실제 동작에 대한 통합 검증은 사용자 저장소에서 필수 선행 단계로 실행된다. 통과하지 못하면 본 실험은 시작하지 않는다. `--addon-only`는 구문·추가 소스 무결성 검사일 뿐 native 검증이 아니다.

## 사용자 환경에서 수행하도록 포함한 검증

기존 전체 source 무결성과 native API, R044/R045 단위검사, 기존 EXP-25 전체 raw verify를 확인한다. EXP-25 4조건의 새 native 회귀와 별도 ±0.85 smoke 6조건이 이어진다. 올바른 답·macro 선택·비용 감소를 self-test 통과 요건으로 요구하지 않는다. 이 10회는 EXP-26 연구 모집단 밖에 둔다.

12개 본 실험은 plan 동결 뒤 한 번씩 실행하며 producer는 raw_complete만 표시한다. 독립 audit와 다시 계산하는 verify가 끝나야 정상 evidence ZIP이 생성된다. 검열·오답·미노출·예측 실패는 raw와 summary에 남는다.
