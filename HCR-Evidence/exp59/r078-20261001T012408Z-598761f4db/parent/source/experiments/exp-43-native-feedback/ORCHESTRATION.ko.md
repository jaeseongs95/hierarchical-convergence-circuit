# R062 실행 분류와 연결

이번 요청은 승인된 순서의 첫 판별 실험이다. orchestrator가 instruction-scope-resolution → task-contract-definition → change-scope-baseline-capture → minimal-implementation → change-scope-assurance → acceptance-evidence-validation 순서로 분류했다. 설치된 스킬 문서와 직접 CLI를 사용하며 MCP guarded workflow를 실행했다고 주장하지 않는다.

선정: task-contract(priority 50, phase 30), change-scope-guardian(phase 42/60), ponytail(phase 44), acceptance-evidence-validator(phase 70). 기존 root AGENTS 적용을 유지하며 추가 하위 지침은 없다. 낯선 다단계 연구 장치의 개발 조정 지침을 적용하되 직접 순차 작업한다. subagent와 별도 연구자 감사는 사용하지 않는다. 외부 배포·권한·데이터 삭제가 없는 로컬 연구 addon이므로 고위험 release audit 대상은 아니다.

TaskEnvelope와 수정 전 baseline은 HCR-Evidence/r062-validation에 저장했다. 기존 untracked 자산은 범위에서 제외한다. 연구 실패는 이론 실패와 분리하며 단일 실행과 source freeze를 증거로 연결한다. 구체적 결과·scope/acceptance 판정은 실행 후 validation artifact와 결과 보고서를 따른다.
