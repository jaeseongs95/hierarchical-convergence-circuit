# R0.3.8 / EXP-19 배포 검증 기록

## 완료한 작업

`main`의 `d25f4bd4e3bd8c8aae763e3ee6542dbfd590900f`를 기준으로 기존 native 엔진, R037 온라인 제어기, R035 selector를 변경하지 않는 추가형 실험 소스를 작성했다. GitHub commit/push는 수행하지 않았다.

세 실험군은 `native`, `posthoc_support`, `online_support`다. 기존 8개 입력에 사전 정의된 3갈래 topology 6개를 추가하고, 2개 prior를 비교한다. 예정된 본 실험은 84개 fresh native session이며 아래 self-test와 구분한다.

원 로그는 같은 폴더의 `unit_tests.txt`, `selector_tests.txt`, `r037_unit_regression.txt`, `r037_selector_regression.txt`에 있다. 환경/범위와 정확한 소스 pin은 `environment_and_scope.json`, 문법 검사 목록은 `syntax.json`에 있다.

## 테스트에서 확인한 계약

합성 경계에서 native와 posthoc은 동일 native 작업을 수행하고, online만 채택 이후 남은 작업을 수행하지 않는다. 이는 제어기 계약 검증이지 실제 native 절감 결과가 아니다. 실제 R035 선택기 연결에서는 지원 proof 선택, missing/zero 비지원, raw 값 보존, 입력 불변성, 선택 예산 및 proof 비용 분리를 검사했다.

최초 native candidate를 selector보다 먼저 journal에 보존하며, 사후 선택이 native 상태/원 판단을 수정하지 않도록 검사한다. 현재 terminal readout이 없거나 추가 계산 중 중단된 상태에서 과거 readout을 최종 판단으로 채택하는 동작을 거부한다. 알 수 없는 ID/parent를 고쳐서 통과시키지 않는다.

가정 수는 `assumptions_checked`, `supported_assumptions`, `unsupported_assumptions`로 분리한다. 보고서 조작, 입력 계약 위반, 출력값 변조, 출처 checksum 불일치, 재실행/덮어쓰기를 거부하는 테스트를 포함한다. 생산 execute에 합성 backend를 넣으면 실제 native 성공으로 저장하지 않고 최초 실패를 보존하는 것도 검사했다.

## 기준선 대조

컨테이너의 원 R037 배포와 import hotfix를 현재 R037 manifest 및 각 파일 SHA256과 대조했다. 실제 R035 `contracts.py`, `selection.py`는 가져온 원문과 Git blob hash를 대조했다. 그 두 기존 파일을 이번 추가형 ZIP에 다시 넣어 덮어쓰지 않는다.

신규 배포 파일은 `R038_MANIFEST.json`으로 검사한다. `scripts/verify_r038.py --addon-only`는 ZIP 자체의 무결성 검사이며 native 통합 검사가 아니다. 전체 저장소에서 옵션 없이 실행하면 동결한 기존 의존 파일까지 대조한다. 소스는 CRLF/LF 차이만 정규화하며 실험 raw evidence는 원본 바이트 해시를 유지한다.

## 실제 남아 있는 검증 범위

이 작업 컨테이너에는 전체 `src/hcr`, R036 의존 소스, EXP18 전체 원자료 capsule이 없으므로 **native 통합 테스트 8개 / 기존 입력 12 session**, **기존 EXP18 전체 독립 재생**, **신규 EXP19 본 실험 84 session**은 실행하지 않았다. 누락을 skip/pass로 표시하지 않았고, 합성 결과를 native 결과로 사용하지 않았다.

저장소에 적용한 뒤 `Run-HCR-R038.py`는 기존 EXP18 전체 독립 재검증과 실제 native 통합 검사를 먼저 수행한다. 첫 실패에서 중단하고 로그를 보존한다. 두 단계가 통과해야 본 실험 계획을 동결하고 실행한다. Native 통합 사전 검사는 이미 사용한 기존 2개 대조 입력만 사용하며 신규 6개 topology를 사전에 실행·선별하지 않는다.

## 결과 해석 기준

새 소스가 조사하는 것은 “지지 경로가 완성됐지만 frontier가 남은 경계가 실제로 발생하는가, 그 경계에서 온라인 채택이 동일 지지 출력을 유지하며 native 작업을 줄이는가”다. 기회 발생·정답·절감을 audit 통과 조건으로 넣지 않는다. 기회가 없으면 판별 경계 미발생으로 기록한다. 지원된 오답의 빠른 종료는 올바른 정답 보존 절감과 분리한다.

Kernel ticks, selector 검사 수, proof 생성 수는 서로 다른 비용 단위다. 본 실험 전에는 native 비용 절감이나 새 topology 일반화 성과를 주장하지 않는다.
